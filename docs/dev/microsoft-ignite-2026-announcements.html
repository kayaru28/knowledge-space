Microsoft Ignite 2026（11月17日）の発表から：Perception と Copilot Managed Runtime と Database Hub が一般提供、Windows Server 2028 はパブリックプレビュー

2026年11月17日の Microsoft Ignite で、Microsoft が公式ブログで発表した4件（Microsoft Perception、Copilot Managed Runtime、Windows Server 2028、Database Hub in Microsoft Fabric）の内容と、提供の状態（一般提供・プレビュー）を、Microsoft の公式ブログをもとに整理する。

初回公開 2026-11-21 ／ 更新日 2026-11-28

ひとことで言うと

Microsoft は、2026年11月17日の Microsoft Ignite で、4件の発表を公式ブログに載せました。Microsoft Perception（Project Perception から名称を変え、一般提供）、Copilot Managed Runtime（一般提供。テナントへの提供を順次開始）、Database Hub in Microsoft Fabric（一般提供）、そしてWindows Server 2028（パブリックプレビュー）です。

このまとめは、4件の公式ブログの内容を、提供の状態（一般提供とプレビュー）を分けて整理したものです。数字や性能の主張は、いずれも Microsoft 自身の記述です。

11月28日に、データベース関連の2件（Oracle からの移行支援と、ローカルで動く Azure SQL Database のコンテナ。どちらもプレビュー）を追記しました。

Microsoft Perception：赤・青・緑のエージェント

  • 構成：赤のエージェントは、侵害につながる経路を見つけて検証する。青のエージェントは、警告の選別、攻撃の調査、脅威情報の検知への変換を行う。緑のエージェントは、重要な露出（弱点）を特定し、対処を調整する。プレイブックが、特定の成果のために、適切なエージェントをまとめる。チャットで頼むこともできる。
  • Triage Agent：Microsoft Defender の典型的なキューの警告の約80%を判定し、結論と理由を示す。Microsoft の分析（Defender の各ワークロードで生成された約800万件の警告。低〜高の深刻度で、最も多く、SOC が対応する警告）による割合で、全体の集計であり、個々の顧客での処理率の保証ではない、と注記している。
  • Attack Investigation Agent：端末、ID、メール、Active Directory、クラウドの資源などをまたいで考え、攻撃のタイムラインを再構成し、侵害されたものを特定し、アカウントの封じ込めや端末の隔離などの対応を、優先順位をつけて提案する。トリガーで、先に自動で動かすこともできる。
  • 第三者のシグナル：Attack Investigation は Okta と AWS、Detection Authoring は Okta・Salesforce・AWS、Triage は Okta と Salesforce のシグナルを扱える。ほかのベンダーは、今後数か月で対応する、と書く。
  • 脅威情報：Threat Intelligence Agent が、外部の脅威に関する記事を、攻撃者の行動や手法、痕跡の構造化された所見にする。「Detect emerging threats」プレイブックで、Detection Authoring Agent が、テナントに合わせた KQL の検知の提案にする。有効にする前に、過去のテナントのデータでテストし、警告の量を見積もる。分析者が確認・調整してから展開する。
  • Web アプリのペネトレーションテスト：Web App Pen Test Agent が、許可された Web アプリを、攻撃者の視点でテストする。認証、API、インジェクション、業務ロジックなどを調べ、弱点ごとに、証拠、影響を受けるエンドポイント、深刻度、概念実証を示す。Microsoft は、Incalmo による独立したベンチマークで、平均の課題解決率が31.0%（OpenAI Codex は15.2%）、安全制約のあるテストの91%で指定の範囲にとどまった、と書く。
  • 防御への接続：「Protect web app」プレイブックで、Risk Reduction Agent が、Azure Front Door の WAF のルール変更などの、露出を減らす対策を提案する。「Reduce exposure risk」プレイブックでは、恒久的な修正が出たとき、Intune 経由のパッチの適用を調整し、すぐに適用できないときは、脆弱性を遮蔽する保護を提供する。
  • コードの脆弱性の探索（MDASH）：コード名 MDASH が、大きなリポジトリを論理的な単位に分けて、段階的に分析する。MAI-Cyber-1.1-Flash と MAI-Cyber-2（プレビュー）のモデルに対応を広げた。Defender のポータル、コマンドライン、GitHub Actions、Azure DevOps で動かせる。
  • つなぎ方：API と Model Context Protocol（MCP）で、ITSM、SIEM、SOAR のツールから、プレイブックを開始できる。エージェントの利用状況のダッシュボードと、費用の計算ツールも出す。Microsoft 365 E7 とあわせて、AI エージェント自体のリスクを調べる機能も広げる。

Copilot Managed Runtime：AI で作ったアプリを、仕事で使える形にする

  • 経緯：9月にパブリックプレビューで発表され、Ignite で一般提供を発表した。テナントへの提供を順次始めている。
  • 中身：Microsoft が運営するホスティングに、Entra のサインインと共有、IT が決めた範囲での、組織のデータやサービスへの接続、アプリのライフサイクル管理を合わせたもの。作る場所は、Copilot Code、Copilot Cowork、Copilot Studio、GitHub Copilot、VS Code、第三者の開発ツールなど。コードは編集でき、Git で管理される。GitHub Enterprise を使う組織は、自前のリポジトリにつなげる。
  • IT の管理：Entra の ID・共有・アクセスに、ポリシーの適用と監査ログが並ぶ。Microsoft 365 管理センターの、アプリの一覧と監視で、公開されたアプリを一覧できる。
  • プレビューの機能：Microsoft Fabric との連携（最先端のパブリックプレビュー）で、アプリ自身の業務データを置く場所を出す（SharePoint と Dataverse への接続に加えて）。Copilot Studio のエージェントとワークフローを、ローカルで作り、CLI で Copilot Studio に公開する（パブリックプレビュー）。コードでエージェントを書く Code Agents は、アーリーアクセスのプレビューで、申し込みと承認が要る。

Windows Server 2028：パブリックプレビュー

  • 提供の仕方：セキュリティ、性能、管理の機能は、Windows Server Insider Program のプレビューで使える。ハイブリッドのインテリジェンス（AI の推論）の機能は、限られた顧客に、アーリーアクセスのプログラムで提供する。ハードウェアの要件がある。
  • セキュリティ：既定で強化した Server Core の構成と、新しいセキュリティのベースライン。Trusted Launch で、VM のブートの完全性を守る。Confidential VM の対応を始める。証明書の自動管理と、耐量子暗号にも投資する。
  • ストレージ：ネイティブの NVMe の対応が、既定で有効。NVMe over TCP と RDMA、ReFS からの起動に対応する。
  • 管理：Intune による Windows Server の管理が、プレビュー。Windows Admin Center の Virtualization Mode は、一般提供。
  • AI の推論：AMD の Instinct MI350P のカードが、2027年前半から、サポート中の Windows Server と Windows Server 2028 でプレビューになる。推論の環境を配備・設定し、アクセラレーターを管理し、モデルへのリクエストを適切な環境に振り向ける機能を開発中。オープンウェイトやカスタムのモデルを、Foundry Local、Windows ML、vLLM、Llama.cpp などで動かせるようにする。分離には Microsoft eXecution Containers、モデルのカタログには Microsoft Foundry、エージェントの ID と統制には Agent 365 を使う。

Database Hub in Microsoft Fabric：データベース全体を1か所で

  • 一般提供：全体の状況（セキュリティ、性能、最適化で何に注意が要るか）、資産の一覧、性能の監視（CPU、メモリ、ストレージの傾向。Cosmos DB は正規化した RU と、制限された要求）、セキュリティの状況（公開のネットワークアクセス、プライベートエンドポイントがないこと、Microsoft Entra の認証、監査ログ、顧客管理の鍵など）、調査。対象は、Azure SQL、Azure Database for PostgreSQL、Azure Cosmos DB、SQL Server、Fabric の SQL database。
  • 一般提供で加わったもの：性能の監視を、複数のリソースで一括して有効にする機能。最適化の洞察（移行評価の準備ができたリソース、従量課金などのライセンスモデルの機会、使用量を報告していない SQL Server）。SQL、PostgreSQL、Cosmos DB のリアルタイムダッシュボード。SSMS と VS Code の拡張機能から開く入口。GitHub Copilot CLI、VS Code の Copilot、Claude Code、Cursor から使える CLI のスキル。
  • 始め方：Fabric が初めてでも、Database Hub を開くと、無料の Fabric のライセンスが自動で付く。ダッシュボードの共有、独自のアラート、Copilot の利用には、Fabric の容量が要る。
  • プレビュー：Copilot で、自然な言葉で、データベース全体を調べる（パブリックプレビュー）。Database Agents は、選んだデータベースを見張り、判断が要るときに、証拠と推奨を添えて課題を上げる（パブリックプレビュー）。Azure SQL Database のアラート（Teams への通知や Power Automate のフロー。Fabric Activator が動力。パブリックプレビュー）。Azure VM 上の SQL Server の性能の監視（プレビュー）。

Oracle から PostgreSQL への移行

  • 提供の状態：Azure Database Migration Service（DMS）の、Oracle から PostgreSQL へのデータ移行の対応は、プレビューです。
  • 分担：評価、スキーマの変換、アプリの変換は VS Code の PostgreSQL 拡張機能、データの移動は DMS が受け持ちます。
  • スキーマの変換：拡張機能が AI を使って Oracle のスキーマを変換し、コンパイルで確かめます。人が確認してから、Azure Database for PostgreSQL のフレキシブルサーバーか Azure HorizonDB に展開します。
  • データの移行：Oracle Database 19c 以降が対象のオフライン移行です。ある時点の写しを移すため、そのあとの変更は同期されず、コピー、検証、切り替えが終わるまでアプリは使えません。対象はスキーマ単位で、対応するリージョンに Japan East を含みます。
  • Azure Database for PostgreSQL から Azure HorizonDB への、DMS を使う移行もプレビューです。

ローカルで動く Azure SQL Database のコンテナ

  • 提供の状態：パブリックプレビューです。
  • 中身：Azure SQL Database のエンジンを手元で動かします。x64 と ARM64（Apple Silicon を含む）で動き、イメージの取得後はオフラインで使えます。ローカルの開発に Azure の契約は要りません。
  • 必要な環境：Docker や Podman などの実行環境、CPU 2コア、メモリ 4GB、空きディスク 10GB。
  • 用途：開発、自動テスト、継続的インテグレーションです。本番用ではなく、管理サービスを完全に再現するものでもありません。
  • 含まれない機能：監査、バックアップと復元、変更データキャプチャ、変更イベントストリーミング、グローバルクエリ、セキュアエンクレーブ付きの Always Encrypted、Azure Key Vault との連携。ARM64 では、全文検索と PolyBase の Parquet 対応がまだ使えません。
  • 公式の記述の違い：Book of News は使える機能の例にセキュアエンクレーブを挙げますが、開発者向けの FAQ は含まれない機能にしています。使う前に確認が必要です。
