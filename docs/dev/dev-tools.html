SvelteKit 3：移行が必要な更新

SvelteKit 3 は、使い勝手はほぼ同じで、型安全性と洗練度が高まった、と Svelte チームは説明しています。一方で、設定の場所や最低バージョンなど、破壊的変更が多いので、既存のアプリには移行の作業が要ります。

設定の場所

  • svelte.config.js はサポートされなくなった
  • 設定は vite.config.js の sveltekit() プラグインに渡す
  • config.kit.* は、プラグインのトップレベルオプションになる

$lib から #lib へ

  • $lib は自動生成されなくなった
  • package.json の imports で #lib を定義する
  • インポートには拡張子が必要

削除・置き換えられた設定

  • csrf.checkOrigin は csrf.trustedOrigins に
  • prerender.origin は paths.origin に
  • vitePlugin、preloadStrategy、files.lib は削除

$app の変更

  • $app/environment は $app/env に
  • $app/stores は削除（$app/state を使う）
  • base、assets、resolveRoute は削除（asset と resolve）

セキュリティ

  • CSRF 保護は常に有効
  • Content-Type ヘッダーのない異オリジンのフォーム送信（変更系）は拒否される
  • Cookie は cookie v2 に。path の既定値は '/'

bun check：型チェックだけを速くする

Bun v1.4.3 の bun check は、tsconfig.json を読み込んで、tsc と同じエラーを報告する、組み込みの型チェッカーです。型チェックのみで、JavaScript や .d.ts は出力せず、言語サーバーもありません。エディタは引き続き TypeScript を使います。次の図は、Bun が示した速度の比較です。

正確性についての Bun の記載

  • TypeScript 7.0.2 の適合テスト51,210件が、すべて合格したとしています。
  • 実プロジェクト72件（1,103の設定）の比較では、不一致は1件（vuejs/core）でした。
  • 別の11種類のコンパイラオプションでの比較（69プロジェクト）では、不一致は12件（strict オフの場合のみ）でした。
  • 大規模なオフライン実行（3,032,182個のプログラム）では、不一致は191件でした。
  • 不一致が見つかったら、Bun のバグとして報告するよう求めています。

HydraFusion：複数のモデルを組み合わせる

HydraFusion は、GitHub Copilot の研究プレビューです。モデルピッカーには1つの選択肢として表示されますが、中では複数のモデルを組み合わせて動きます。リクエストごとに、次のどれかを選びます。

Single

選ばれた1つのモデルが、タスクを直接解きます。

Cascade

効率のよいモデルが下書きを作り、品質ゲートが、採用するか、より強いモデルへ引き継ぐかを判断します。

Critique

あるモデルが下書きを作り、別のモデルファミリーの読み取り専用のクリティックがレビューします。そのあと、下書きを作ったモデルが1回だけ修正します。

  • 使い方：VS Code 1.140 以降（または Insiders）で、Copilot Chat のモデルピッカーから選びます。表示されない場合は、設定 chat.copilot.hydraFusion.enabled を有効にします。
  • 対象：Copilot Pro、Pro+、Business、Enterprise。Business と Enterprise は、管理者がプレビュー機能を有効にする必要があります。
  • 料金：HydraFusion が使ったモデルのトークン量に基づき、各モデルの標準料金で計算されます。
  • 10月14日の更新：上位版の HydraFusion Max が加わりました。モデルプールは、Claude Opus 5.5、GPT-6 Astra、GPT-6.1 Sol、GPT-6 Luna です。
  • GitHub が述べている限界：中間の下書きは最終結果まで表示されないため、待ち時間の見通しが悪い。現時点では単発のタスクに適していて、複数ターンの長いセッションは今後の課題です。

Aurora PostgreSQL：データレイクを直接クエリする

Aurora PostgreSQL で、S3 などにある Iceberg や Parquet のデータを、運用データと一緒に、同じ SQL で問い合わせられるようになりました。ETL やデータの複製は要りません。

  • 対応：Aurora PostgreSQL 17.11、18.6 以降。一般提供です。
  • 設定：Amazon RDS コンソール、または任意の PostgreSQL クライアントで行います。
  • リージョン：すべての AWS 商用リージョンと AWS GovCloud（US）で利用できます。
  • 料金：追加料金はかかりません。
  • このページには、対応バージョンとリージョン以外の具体的な制限は書かれていません。詳細は公式ドキュメントで確認が必要です。

dotnetup：.NET の SDK を管理する

dotnetup は、ユーザーアカウントの中で、.NET の SDK とランタイムを導入・管理・更新するツールチェーンマネージャーです。Rust の rustup や Node の nvm に近い位置づけです。macOS と Linux で、apt、brew、tarball、dotnet-install.sh などが混在していた問題の解消を目指しています。

特徴

  • どのプラットフォームでも同じコマンド
  • 管理者権限は不要。ユーザー所有のフォルダに置く
  • 複数のサービシングバージョン、プレビュー、デイリービルドを同時に入れられる
  • メジャーや機能バンド単位で追跡し、毎月の更新を自動で反映する
  • global.json に対応し、チームビルドの再現性を保つ

使い方の例

  • dotnetup init：シェルプロファイルを設定し、最新の安定版 SDK を取得
  • dotnetup list：インストール済みの一覧
  • dotnetup update：月次の更新
  • dotnetup sdk install preview、dotnetup sdk install daily
  • dotnetup self update

制約と今後

  • パブリックプレビュー。機能や動作は変わる可能性がある
  • 現時点では、ユーザーローカルの運用に限られる
  • Windows のシステムレベル（管理者）のインストールの管理は、将来のリリースで検討
  • ロードマップ：Windows 管理者インストーラー、GitHub Actions や Azure DevOps への統合、UX の改善

dotnet-install のスクリプトでも多くのことはできますが、dotnetup は、インストール済みの管理、署名と checksum の検証、複数の SDK／ランタイムの高速な導入、全プラットフォームで共通の CLI が利点だと、記事は説明しています。

選ぶときの観点

各社の発表を並べて読んだ上での、筆者の整理です。各社がそう述べているわけではありません。

  • 手を動かす必要があるか: SvelteKit 3 を使っているなら移行が必要。ほかは新機能を試すかどうかを選べる。
  • 提供状況: プレビューのものは、業務の中心には置かず、試す範囲にとどめる。
  • 数字の見方: bun check の速度やメモリ、HydraFusion のコスト削減は、開発元の測定で、条件が限られる。自分のプロジェクトで測る。
  • 置き換えか、追加か: bun check は tsc の代わりに型チェックだけを行う。言語サーバーや出力はない。

用語メモ

Iceberg / Parquet
Iceberg は大規模なデータ分析用のテーブル形式。Parquet は列指向のファイル形式。
DuckDB
組み込んで使える分析用のデータベースエンジン。
外部テーブル（foreign table）
データを取り込まずに、外部のデータをテーブルのように参照する仕組み。
ツールチェーンマネージャー
複数のバージョンの開発ツールを切り替えて管理するツール（rustup や nvm など）。
研究プレビュー
正式な提供の前に、試験的に使ってもらうための提供。仕様は変わりうる。
適合テスト
言語の仕様どおりに動くかを確かめるためのテスト群。
