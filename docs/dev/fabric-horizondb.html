Microsoft Fabric HorizonDB（パブリックプレビュー）：Fabric の中の PostgreSQL。使えるのは作成者本人だけという、現時点の制限

Microsoft Fabric の中で提供される、サーバーレスの PostgreSQL「Fabric HorizonDB」の、仕組み、Fabric との連携（ミラーリング、フェデレーテッドクエリ、データ配信）、パブリックプレビューの制限を、Microsoft Learn の概要ページと制限のページをもとに整理する。

初回公開 2026-11-20 ／ 更新日 2026-11-20

ひとことで言うと

Fabric HorizonDB は、Microsoft Fabric の中で提供される、PostgreSQL のマネージドサービスです。1つ1つのデータベースは、Fabric の部品（アイテム）で、アプリは PostgreSQL のプロトコルで接続し、計算、保存、保守、分析との連携は、Fabric が管理します。現在はパブリックプレビューで、機能や制限は、一般提供の前に変わりうる、と Microsoft は書いています。

現時点の大きな制限は、データベースを作った Microsoft Entra の ID だけが接続できることです。ほかのユーザー、サービスプリンシパル、マネージド ID は接続できず、Fabric のアイテムを共有しても、解除されません。Microsoft は、開発・テスト用のワークスペースと、機微でない合成データを使うよう求めています。

仕組み

  • Fabric のアイテム：データベースごとに、安定した PostgreSQL のエンドポイントを持つ。永続のデータと、顧客が使う計算を分けるため、データベースの同一性とエンドポイントを変えずに、計算を調整できる。
  • 自動で拡縮：顧客が計算の大きさを選ぶのではなく、サービスが管理する資源を、プラットフォームが負荷に応じて自動で調整する。
  • ゼロまでの縮小：有効な場合、使われていないデータベースは一時停止し、同じエンドポイントへの接続で再開する。再開には、起動の遅れがある。一時停止の間も、永続のデータ、設定、ID の結びつき、エンドポイントは残る。セッション、一時的な状態、揮発性のキャッシュは、一時停止、拡縮、保守のあとに残る保証がない。
  • 接続の方法：Fabric の SQL エディター、Visual Studio Code の Microsoft PostgreSQL 拡張、PostgreSQL 互換のクライアント。運用の接続は、PostgreSQL のエンドポイントを使う。SQL 分析エンドポイントは、ミラーしたデータを読むだけの、別の面。

Fabric との連携：3つの経路

概要ページが示す「Federated Analytics（連携した分析）」の3つの機能
機能向き使う場面
データベースのミラーリングHorizonDB から Fabric へ分析する側が、運用データの対象のテーブルの、非同期のコピーを、OneLake と SQL 分析エンドポイントで使いたいとき
フェデレーテッドクエリFabric から PostgreSQL のクエリへ運用のクエリが、対応する Fabric のデータを、pg_fabric_fdw で、ローカルのテーブルにコピーせずに読みたいとき
データ配信Fabric から HorizonDB の保存へ分析の結果の一部を、アプリのために、PostgreSQL に実体として持たせたいとき（上限つきの Copy ジョブによる、いわゆるリバース ETL）

3つの経路は、健全さと鮮度が、それぞれ独立しています。PostgreSQL のエンドポイントが正常でも、ミラーリング、フェデレーション、Copy ジョブが正常とは限らず、ミラーしたデータは、運用のデータベースより遅れうる、と書かれています。

組み込みの拡張

  • vector、pg_diskann、pg_textsearch：承認された、ベクトル検索と全文検索の用途のため。
  • pg_fabric_fdw：対応する Fabric のデータを、クエリで読むため。
  • azure_ai：承認された AI の操作の連携の入口。拡張があることは、モデルの提供元、エンドポイント、割り当て、権限があることを意味しない、と書く。
  • サービスが作って管理する拡張（と、既定の fabric_dw という外部サーバー）は、削除、置き換え、変更をしてはならない。使える拡張は、プレビューの環境で異なりうるため、pg_extension で確かめる。

ミラーリング対象は、条件を満たすテーブル、キー、データ型、DDL だけ。最初にコピーし、そのあと、コミットされた変更を非同期に反映する。遅れの数値の保証は公表されていない。関数、サービスのスキーマ、一時テーブル、非対応の型、ラージオブジェクト、拡張が所有するオブジェクトなどは、ミラーされる保証がない。テーブルが対象外になる変更で、ミラーリングが止まり、修復や再初期化が必要になることもある
フェデレーテッドクエリ対応する Fabric の SQL 互換のエンドポイント、ワークスペース、型、ID の流れは、公開された一覧に限る。外部テーブルは読み取り専用で、INSERT、UPDATE、DELETE、MERGE、FOR UPDATE などは使えない

用語メモ

Microsoft Fabric
Microsoft の、データの収集、保存、分析を一体で扱う基盤。
OneLake
Fabric のデータの置き場。ミラーしたデータが入る。

運用のデータベースの内容を、分析の側に、非同期で複製し続けること。
