開発ツールの2つの更新：DuckDB 2.0 LTS（Quack、非同期 I/O、VARIANT、トリガー、エージェントモード）と、Bun 1.4.4 の bun fmt

2026年10月21日に出た DuckDB 2.0 LTS の新機能・移行の注意・取り除かれるものと、10月22日の Bun 1.4.4 に入った Prettier 互換の整形ツール bun fmt の互換性・速度・設定を、公式の発表から整理する。

初回公開 2026-10-30 ／ 更新日 2026-10-30

ひとことで言うと

DuckDB 2.0 は、長期サポート（LTS）版として2026年10月21日に出ました。サーバーとして使う Quack、非同期 I/O、VARIANT 型、トリガー、新しい SQL パーサ、コーディングエージェント向けの出力モードが入っています。ただし、2.0 より前の DuckDB は、2.0 が作ったデータベースのファイルを読めません。

Bun 1.4.4（10月22日）には、Prettier と互換のコード整形ツール bun fmt が入りました。Prettier の整形テストの99.1%で出力が一致し、Prettier 本体のリポジトリでは、確認が286倍速かった、と Bun は書いています（Bun の測定です）。

主な新機能

Quack：サーバーとして使う

1.5.3 で導入されたプロトコルが洗練され、性能と安定性が上がりました。quack 拡張でサーバーを立てられ、既定では localhost だけで待ち受けます。他のマシンから接続するには、TLS を終端するリバースプロキシの背後に置くことが推奨されています。新しい CONNECT 文で、リモートの DB へのアタッチと切り替えを1コマンドでできます（PostgreSQL や MySQL も対象）。リモートでは、テーブルを転送せず、サーバーに直接クエリを送る最適化（pushdown）が働きます。

非同期 I/O

Parquet、CSV、ネイティブの格納形式の読み取りに適用されます。I/O の層が問い合わせ処理から独立し、複数の要求を同時に出せます。s3:// などのオブジェクトストレージ上のクエリが大きく速くなるとされますが、具体的な倍率は本文にありません。

VARIANT 型

共通の構造を見つけて分解して持ち、圧縮と実行速度を上げる型です。Parquet でも、分解した形での読み書きに対応します。variant_* の関数が加わりました。

エージェントモード（CLI）

コーディングエージェントからの実行を検出して、自動で切り替わります。コンパクトな Markdown の表で出力し、切り詰めを明示し、暴走したクエリを早く止め、エラーを JSON で返します。長いクエリは、実行前に想定の費用を報告します。TPC-H の実験では、モデルが読む DuckDB の出力量が59%減りました。-agent で有効、-no-agent で無効です。

トリガー

BEFORE／AFTER、FOR EACH ROW／FOR EACH STATEMENT、REFERENCING OLD/NEW TABLE、イベントごとに複数のトリガー、RETURNING に対応します。制限として、BEFORE ... FOR EACH ROW と UPDATE ... FOR EACH ROW はまだ未対応です。

PEG パーサ

新しい SQL パーサが既定になりました。以前は YACC/Bison の LALR(1) でした。文法の拡張が可能になり、エラーの位置が正確になります。旧パーサには SET enable_legacy_parser = true; で戻せます。意図した差分は、移行ガイドに書かれています。

  • 拡張の開発・配布：C API v2 を刷新し（意見募集中）、独自の拡張リポジトリを登録して、署名つきの拡張を配れます。作業中の機能で、構文が変わる可能性があります。
  • コア拡張：DuckLake 1.1。Iceberg の REST catalog の ATTACH オプション。Delta の CREATE TABLE（パーティションとプロパティ）、タイムトラベル、VARIANT 対応の改善。
  • SQL：$variable 記法、データを変更する CTE、NEAREST 結合、入れ子のスキーマ、JSON を変更する関数、FETCH FIRST、GROUP BY での UNNEST が加わりました。MERGE と UPDATE ... FROM で複数に一致したときの挙動が、明確になりました。

移行の注意

ファイルの互換性は一方向

2.0 より前の DuckDB は、2.0 が作ったデータベースのファイルを読めません。2.0 は既存のファイルを読み書きでき、そのファイルは旧版でも引き続き読めます。

検証と待つ時期

本番の移行の前に、シャドー環境での検証が推奨されています。ミッションクリティカルな用途では、11月に予定される最初のパッチリリースまで待つことが勧められています。

取り除かれる・変わるもの

  • C++17 のコンパイラが必須になりました。リリースビルドの既定は Clang です。
  • ICU は廃止されました。タイムゾーン、カレンダー、照合順序は icu 拡張が自前で実装し、タイムゾーンのデータは約45kBです。
  • 単一矢印のラムダ（x -> x + 1）は既定で無効です。SET lambda_syntax = 'enable_single_arrow'; で一時的に戻せます。どちらも v2.1 で削除予定です。
  • amalgamation ビルドは非推奨です。macOS の x86_64 は段階的に縮小され、v2.1 でサポートが終わります。

Bun 1.4.4 の bun fmt

Bun の公式ブログは、bun fmt を「非常に速い、Prettier 互換のコード整形ツール」と紹介しています。対応する形式は、JavaScript、TypeScript、JSX、Flow、CSS、SCSS、Less、HTML、Vue、Svelte、Angular、LWC、MJML、JSON、JSONC、JSON5、YAML、TOML、Markdown、MDX、GraphQL、Handlebars です。

設定と組み込みの機能

  • 読み込む設定：Prettier 系（.prettierrc*、prettier.config.*、package.json の "prettier"、overrides、.editorconfig、.prettierignore）、oxfmt 系（.oxfmtrc.json など）、Bun 独自の bunfig.toml の [fmt]。
  • 組み込みの機能：import の並べ替え、Tailwind のクラスの並べ替え（Tailwind 3 か 4 が必要）、package.json のキーの並べ替え、Svelte の整形、jsdoc。Svelte の整形は既定で有効で、そのほかは既定でオフです。
  • 対応していない Prettier のプラグイン：エラーを出して該当ファイルを飛ばし、終了コード2で終わります。
  • CLI：--check（書き込まずに一覧。要整形なら終了コード1）、--staged、--changed、--doctor（設定の解釈と、削除できるパッケージを表示）、--debug-check（整形の前後で意味が変わっていないかを再パースして確認）。

Prettier との意図的な違い

意味を変えないために、Prettier とは違う出力にする例が、4つ挙げられています。

  • CSS の font-family: Font\ Awesome：Prettier は Font\Awesome に変えますが、bun fmt は保持します。
  • CSS セレクタの x |b：Prettier は名前空間のセレクタ x|b に変えますが、保持します。
  • Handlebars の <!DOCTYPE html>：Prettier は削りますが、保持します。
  • Handlebars の <script> 内の // コメント：Prettier は行を結合してコメントが後続の行を飲み込みますが、保持します。

同じ版のそのほかの変更（一部）

  • bun check：大きなプロジェクトで1.4倍から7.8倍速くなりました（MUI の docs は10.28秒から1.31秒、ピークメモリは 11.2GB から 1.3GB）。
  • bun install：Yarn Berry（2以降）の yarn.lock を bun.lock へ移行できます。リトライは指数バックオフ（50ミリ秒起点、最大5回）になりました。Linux の hoisted リンカーが、ウォームキャッシュで最大3.2倍速くなりました。
  • Bun.SQL：クエリごとのクライアント CPU 使用量が最大48%減りました。PostgreSQL で query.cancel() が動きます。
  • JavaScriptCore：上流の WebKit のコミットを1,013件取り込みました。
  • 注意：Glob の既存パターンの一部（*(1).txt、{1..3}）は、意味が変わりました。
  • セキュリティ修正が、TLS、WebSocket、DB クライアント、パッケージマネージャーなど、広い範囲に入っています。個別の内容は読んでいません。

読むときの注意

  • DuckDB の「少なくとも2027年10月まで」は、サポートの下限です。前の LTS の 1.4 は2026年11月17日までで、移行の時期の目安になります。
  • DuckDB の非同期 I/O の速さは、倍率が本文にありません。
  • Bun の速度と一致率は、Bun 自身の測定で、第三者の確認は読んでいません。一致率は、種類で大きく違います（整形テストで99.1%、オープンソースの全ファイルの完全一致は、Prettier との比較で77.0%）。
  • bun fmt を既存のプロジェクトに入れると、整形の結果が少し変わりうるため、差分を確かめる必要があります。

見方（筆者の整理）

  • DuckDB 2.0 は、ファイルの形式の互換性が一方向（新しい版が作ったファイルを旧版が読めない）なので、版を混ぜて使う環境では、移行の順序が要になります。
  • サーバー化の Quack は、既定を localhost に絞り、外に出すときは TLS のリバースプロキシを勧めるなど、公開の仕方に注意を促しています。
  • bun fmt は、速度の差が大きい一方で、一致しない例の多くは、意図的な違いだと書かれています。既存のプロジェクトでの差分は、実際に確かめる必要があります。
