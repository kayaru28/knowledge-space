VS Code 1.144：エージェントの既定が Copilot の「ハーネス」になり、モデルを競わせる比較と自動選択（Fusion）、承認の自動化、クラウドでの実行が入った

2026年10月28日公開の Visual Studio Code 1.144 の公式リリースノートから、エージェントの既定のハーネス、他社のハーネス（Claude Code、Codex）への切り替え、モデルの比較と Copilot Fusion、リスク評価つきの承認、クラウドでの実行、エージェントの通信の規格を整理する。

初回公開 2026-10-29 ／ 更新日 2026-10-29

ひとことで言うと

2026年10月28日に公開された VS Code 1.144 のリリースノートによると、エージェントの既定は GitHub Copilot の「ハーネス」になりました。ハーネスは、AI のモデルを使ってエージェントを動かす土台のことです。Anthropic の Claude Code や OpenAI Codex のハーネスに切り替えて、Copilot の契約のまま使うこともできます。

あわせて、同じ指示を複数のモデルに試させる比較、Copilot がモデルを選んで組み合わせるFusion、リスク評価つきの承認の自動化、クラウドでの実行が入りました。

今回の要点（公式のハイライト）

  • セッションの継続：リモートを1か所で管理し、手元のコンピュータが止まっていても、セッションと自動化を動かし続ける。
  • Copilot Fusion とモデルの比較：Copilot が選んで組み合わせる、または並べて比べる。
  • 画像生成（プレビュー）、コンピュータの操作（実験的）：エージェントがデスクトップのアプリを使う。
  • 作業セット（実験的）：エージェントの編集を、エディタで残す、または取り消す。
  • 支援つきの承認：リスク評価に通ったツールの呼び出しを自動で承認。
  • マーケットプレイスとコネクタ（プレビュー）：Slack や Notion などの文脈を、セッションに持ち込む。

ハーネスが既定に

  • 既定：エージェントは Copilot ハーネスで動きます。Copilot のコードレビュー、CLI、アプリ、クラウドのセッションと同じ土台で、カスタマイズを1度書けば、どこでも同じように使えます。
  • 切り替え：Claude Code のハーネスや、OpenAI Codex のハーネスを、Copilot の契約で使えます。
  • 位置づけ：Copilot SDK の上に作られた最新のハーネスで、1.144 でも新しいセッションの既定であり続けます。
  • 作業セット（実験的）：Copilot ハーネスのエージェントの編集を記録し、個別に残す、または取り消せます。端末のコマンドによる変更は含まれません。

モデルの比較と Fusion

リリースノートの説明
機能内容
モデルの比較（Agent Bake-Off）同じ指示を複数のモデルとハーネスで動かし、並べて確認する。対象の新しいセッションで既定で有効。今回、プロジェクトなしの会話や、コミットのない手元のリポジトリでも使えるようになった
Copilot Fusionモデルの選択を Copilot に任せる。リクエストごとに、モデル、推論の強さ、実行の型を選ぶ。簡単なものは1つのモデル、難しいものは1つが下書きし、他のモデルが見直す。強さは Standard / High / Max
料金と提供使ったモデルごとに通常の料金。2026年11月30日まで有料プランは30%割引。一般提供。High と Max は Pro+、Max、Business、Enterprise のプラン

承認の自動化

  • エージェントは、作業のために多くのツールを呼び出します。1回ごとに承認すると煩わしく、すべて任せると事故のおそれがあります。
  • 「支援つきの承認」：呼び出しごとに LLM がリスクを評価し、低リスクのものは自動で実行します。高リスクのものや、判断できないものは、利用者の承認が必要です。
  • Copilot のセッションで一般提供。フォルダの分離が必要で、組織の設定で制限されることがあります。

クラウドでの実行

  • クラウドのセッション：GitHub の管理された環境でタスクを実行します。マシンを起動しておく必要がなく、GitHub.com やモバイルアプリからも進み具合を見られます。手元の未コミットの変更は自動ではコピーされません。有料の Copilot プランが必要です。
  • クラウドの自動化（プレビュー）：スケジュールや、Issue・プルリクエストのイベントで動きます。リポジトリにアクセスできる人に見える形で、チームで共有できます。使えるツールとフィルターで、範囲を決めます。

Agent Host と規格

  • Agent Host：エージェントを動かし続ける別のプロセスです。クライアントを閉じても止まらず、手元でもリモートでも動かせます。
  • Agent Host Protocol（AHP）：エージェントとやり取りする、オープンで拡張できる規格の最初の版が公開されました。独自の画面や、エージェントの基盤をつなぐための規格で、6つの言語のライブラリがあります。

見方（筆者の整理）

  • 注目点は、エージェントを動かす土台（ハーネス）を選べる形になり、他社のものも同じ画面と契約で使える点です。モデルだけでなく、ハーネスも比べる対象になっています。
  • 承認を LLM が評価して自動化する仕組みは、利便性と安全性の折り合いを、判断を AI に任せる形で取ろうとするものです。「判断できない場合は承認を求める」とされているため、この線引きの精度が使いどころになります。
