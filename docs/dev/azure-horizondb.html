Azure HorizonDB：計算と保存を分け、「ログがデータベース」になった、Microsoft の PostgreSQL 互換サービスの仕組みと制限

Microsoft が提供する PostgreSQL 互換のマネージドサービス「Azure HorizonDB」の、アーキテクチャ（計算と保存の分離、ログ中心の設計）、クラスターの構成、AI 機能、料金の考え方、現時点の制限と提供リージョンを、Microsoft Learn の概要ページと製品ページをもとに整理する。

初回公開 2026-11-20 ／ 更新日 2026-11-28

ひとことで言うと

Azure HorizonDB は、Microsoft が出している、PostgreSQL と互換のあるクラウド専用のデータベースサービスです。公式の説明では、計算と保存を完全に分け、さらに「データベースをログとして作る」設計をとることで、予測しやすい性能、可用性、拡張性を出す、と書かれています。

計算側から保存側へ書くのは、先行書き込みログ（WAL）だけで、データのページは書きません。製品ページは、自己管理の PostgreSQL に比べて、最大3倍の処理性能と、最大 3,072 vCore・128 TB まで拡張できる、と書いています（注の条件は未確認）。

Microsoft は2026年11月17日の Ignite で、一般提供を発表しました（11月28日追記）。

設計の2つの原則

計算と保存の分離

計算は状態を持たず、vCore とメモリを、保存と独立に増減できる。保存は、WAL 用と、データ用の2種類の専用のサーバー群で、どちらも Azure のストレージで耐久性を支え、既定でゾーンの障害に耐える。読み取りノードは、データのコピーが要らないため、すぐに追加できる

ログがデータベース

計算側から保存側へ書くのは WAL だけで、データのページは書かない。WAL を真実の元として、保存のノードが、WAL を適用してページを再構築する。これにより、チェックポイントの I/O の詰まりをなくし、書き込みの増幅を減らし、データベースの大きさによらず、安定した書き込みの待ち時間を出す、と書く

書き込みは、(1) アプリが、読み書きのエンドポイント経由で、書き込みのノードに変更を送る、(2) ノードが WAL を WAL 保存に送り、耐久的に保存されてから、アプリに確認を返す、(3) WAL が、データの保存と、すべての読み取りノードに配られ、読み取りノードは、通常、ミリ秒で反映する、(4) WAL とデータのページが、Azure Blob に書かれる、という流れです。

クラスターの構成

概要ページが示す、1つのクラスターの部品
部品説明数
書き込みのノードすべての書き込みを処理する。読み取りも処理できる1
読み取りのノード読み取りを処理する。書き込みのノードが落ちたら、読み書きのプールの読み取りノードが引き継ぐ最大15
読み書きのプール書き込みのノードと、任意で読み取りのノードを含む1
読み取りのプール読み取りのノードだけを含む（※現時点では使えない。下の制限を参照）最大15（概要の表）
読み書きのエンドポイント書き込みのノードに接続する。フェイルオーバーのあとも、接続先が自動で変わる1
読み取り専用のエンドポイントプール内の読み取りノードに、接続を分散するプールごとに1
保存すべてのノードが共有する、データの1つのコピー1

各ノードは、vCore あたり 8 GB のメモリと 32 GB のローカル NVMe SSD のキャッシュを持ちます。ノードは、1つの可用性ゾーンで動き、ゾーン冗長の高可用性にするには、プールに2つ以上のノードが必要です。保存の容量や IOPS は、選ばず、データに合わせて自動で増えます。

AI と分析の機能（製品ページ・概要ページ）

  • AI 機能：ベクトルの埋め込みの対応と、Microsoft Foundry との連携。RAG、レコメンド、意味検索を、データベースの層で作れる、と書く。AI モデルの管理と AI のパイプラインの機能もある。
  • 検索：製品ページは、ベクトル検索、全文検索、ハイブリッド検索、意味による再順位づけを、データベース内で行え、DiskANN が、ベクトル検索と絞り込みを1回の操作で行う、と書く。
  • 分析：データを Microsoft Fabric にミラーリングして、OneLake で、運用データと業務データを合わせられる（製品ページは「ETL なし」と書く）。
  • 互換性：既存の PostgreSQL のクライアント、ドライバー、ORM、SQL がそのまま使える。
  • セキュリティ：PostgreSQL と Microsoft Entra の認証、プライベートエンドポイント、暗号化。製品ページは、各国・地域別を含む50を超える準拠の認証がある、と書く。

クラスターで選べること、選べないこと

  • 作成のときに決め、あとから変えられない：PostgreSQL のメジャーバージョン、データの暗号化の種類、地理冗長バックアップ。
  • バックアップ：保持は1日から35日。バックアップは、保存の層で取り、データベースが大きくても、すぐに終わり、ノードの資源を使わない、と書く。
  • 料金：従量課金。計算は、確保したコアの時間の分、保存は、使ったデータベースの容量（GB の月ごと）と、短期保持のバックアップの使った分（概要ページ。11月19日更新）。製品ページは、バックアップの保存は、合計の保存量の100%まで無料、と書く（具体的な金額は読んでいません）。

現時点の制限（概要ページ）

機能状況・備考
リージョンをまたぐ読み取りノード使えない。災害対策は、地理冗長バックアップと、ペアのリージョンへの復元で行う

その場でのメジャーバージョンの更新使えない
接続プーリング（PgBouncer）使えない。外部の接続プーラーを使う

用語メモ

WAL（先行書き込みログ）
PostgreSQL が、データの変更を、順に記録するログ。ここに書いてから、データに反映する。
フェイルオーバー
書き込みのノードが使えなくなったとき、別のノードに役割を移すこと。

DiskANN
大量のベクトルから、近いものを速く探すための、索引の方式。
OneLake
Microsoft Fabric のデータの置き場。
