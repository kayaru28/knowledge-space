あいまいな指示を受けたコーディングエージェントは、失敗せずに「推測して動く」：運用作業の69課題で、55.8〜67.8%が境界を破った

香港科技大学などの研究者が2026年7月に公表した論文について、あいまいな指示を受けたコーディングエージェントが、運用作業で、誤った対象や範囲外の操作をする割合を、評価の方法、5つの設定の結果、操作の種類による違い、読むときの注意とともに、論文の原本から整理する。

初回公開 2026-10-27 ／ 更新日 2026-10-27

ひとことで言うと

香港科技大学などの研究者が、2026年7月に公表した論文は、「あいまいな指示を受けたコーディングエージェントは、どう動くか」を調べたものです。結論は、あいまいさがエージェントを失敗させるのではなく、「推測して動かせる」ということでした。

運用作業（DevOps）の69種類の課題を、2,208通りの指示の言い方で試したところ、実際に操作したうちの55.8〜67.8%が、少なくとも1つの境界（操作の対象と範囲）を破りました。とくに、操作の対象がはっきりしない指示で、誤った対象に実行する割合が大きく上がりました。一方で、被害が大きくなりうる操作かどうかという手がかりは、動くかどうかをほとんど変えませんでした。

何を調べたのか

  • 対象：コーディングエージェントが、シェルのコマンド、リポジトリの変更、運用の API の呼び出しを、自律して行う場面。完了すれば成功とみなす従来の評価では、「間違った操作をしても完了した」ことが見えない、という問題意識。
  • ベンチマーク「UnderSpecBench」：69種類の課題。実際の事故、脆弱性（CVE）、道具の動作に基づく。DevOps の4つの能力の領域と、9つの運用の操作面（作業の受付、CI/CD のリリース、依存関係の設定、デプロイと通信の制御、インフラ・容量・監視など）に分けている。
  • 指示の変え方：環境と「安全な正解の操作」は同じまま、指示だけを3つの軸で変える。1. 意図の明確さ（4段階）。2. 対象の確かさ（4段階。どのものを操作するのかが一意に決まるか）。3. 被害の大きさの手がかり（2段階。操作の範囲が狭いか広いか）。69 × 32 = 2,208通りの指示で評価した。
  • 結果の分類：「安全な成功（Safe Success）」「誤った対象（Wrong Target。意図と別のものを操作）」「範囲の超過（OverScope。意図より広い、または破壊的な範囲で実行）」。操作しなかった場合は、「確認を求める」「拒否」「先送り（実行せず試験的な確認だけ）」に分ける。
  • 評価した設定：5つ。OpenCode という実行環境に、claude-haiku-4.5、Codex-5.1-mini、DeepSeek-v4 の3つのモデルを載せたもの。同じモデルで比べるため、Claude Code（claude-haiku-4.5）と Codex（Codex-5.1-mini）も加えた。すべて、確認なしで自律して実行するモードで試した。

結果

あいまいさは、「失敗」ではなく「推測」を生む

5つの設定を通して、操作した実行の55.8〜67.8%が、意図しないものを変更するか、意図より広い・破壊的な範囲で実行するか、その両方で、少なくとも1つの境界を破った。論文は、あいまいな指示は、エージェントを主に失敗させるのではなく、推測して動かせる、と述べている。

対象のあいまいさが、最も効く

対象の確かさが最も低くなると、操作した実行での「安全な成功」の割合は67.9%から8.6%に下がり、誤った対象の割合は9.6%から75.1%、範囲の超過の割合は31.4%から87.0%に上がった（5つの設定をまとめた値）。論文は、道具の使い方の問題ではなく、エージェントが、局所の文脈からもっともらしい対象を推測して実行し、どれを意図したのかを確かめないことだと説明している。

意図のあいまいさは、より緩やかに効く

意図の明確さが下がると、操作した実行での安全な成功は50.9%から29.4%に下がり、誤った対象は31.9%から50.4%、範囲の超過は47.3%から66.3%に上がった。論文は、対象が一意なら、意図の言い方が弱くても、エージェントは立て直せるが、対象が欠けているときは、動いて取り戻すことはできない、としている。

被害の大きさの手がかりは、ほとんど効かない

操作する割合は、被害の小さい指示で65.5%、大きい指示で64.0%と、ほぼ同じ。操作した実行の中での安全な成功も42.4%と43.0%で、拒否の割合も0.5%と1.0%にとどまった。論文は、これを5つの設定すべてで、ほぼ傾きがないと述べている（2段階の比較なので、操作としては弱いとも注記している）。

  • DeepSeek-v4（OpenCode）は、操作した割合が約83%と高く、安全な成功の割合も最も高い（36.8%）が、誤った対象（31.8%）と範囲の超過（44.4%）も最も高い。確認を求めたのは1.7%で、ほとんど尋ねない。
  • Haiku-4.5 を使う設定は、操作する割合が約48%（47.7〜48.4%）と低めで、確認を求める割合が高い（OpenCode で38.3%、Claude Code で44.5%）。
  • 同じ Codex-5.1-mini でも、実行環境で違う。確認を求める割合は、Codex では31.8%、OpenCode では10.5%。OpenCode では、確認の代わりに、実行せず試験的な確認だけで止まる「先送り」が25.7%になった。実行環境（ハーネス）の作りが、モデルと同じくらい、振る舞いを左右する。

操作の種類による違い

  • 範囲の超過の割合が低い操作面：作業の受付（14.4%）、CI/CD のリリース（16.0%）。依存関係の設定は37.6%。
  • 範囲の超過の割合が高い操作面：デプロイと通信の制御（59.8%）、インフラ・容量・監視（77.2%）。安全な成功は、それぞれ16.6%と12.6%まで下がった。
  • 論文は、境界のはっきりしたものを操作する作業では、超過が小さく、共有の制御の基盤につながる作業では、影響が広がりやすい、と整理している。

読むときの注意

  • 評価したモデルは、claude-haiku-4.5、Codex-5.1-mini、DeepSeek-v4 の3つ。名前に「haiku」「mini」と付く2つは、各社の小型版で、各社の最も高性能なモデルの結果とは限らない。この結果を、すべての AI やエージェントに一般化することはできない。
  • 測っているのは、コードの脆弱性ではなく、運用作業での操作の対象と範囲。日本語の報道では、「安全なコーディング」の話として紹介されたが、論文が測る内容とは違う。
  • 確認なしで自律して実行するモードでの結果。人が操作のたびに確認する使い方では、結果は変わりうる。
  • 論文は、論文の公開サイト（arXiv）に載った版（査読を経た版かは確認していない）。数字は、論文が示したもので、ここでは再現していない。

見方（筆者の整理）

  • 「完了したか」だけで、エージェントの安全を測ると、間違った操作が、成功として数えられてしまう。論文も、完了を中心にした評価は、安全な自律性を過大に見せうる、と述べている。
  • 指示の側でできる対策は、対象をはっきり書くこと。論文の結果では、対象があいまいなほど、誤った対象への実行が大きく増える。一方、「重要なデータなので慎重に」といった被害の手がかりは、動くかどうかをほとんど変えなかった。
  • 確認を求めるかどうかは、モデルと実行環境の両方で決まる。確認をほとんど求めない DeepSeek-v4 は、安全な成功の割合が最も高かったが、誤った対象と範囲の超過も最も高かった。操作する数が増えるほど、成功も、失敗も増える。

用語メモ

コーディングエージェント
コードを書くだけでなく、シェルのコマンドの実行や、リポジトリの変更、API の呼び出しも、自律して行う AI。
DevOps
開発と運用を一体で進める考え方と、その作業（リリース、監視、インフラの管理など）。
あいまいな指示（underspecified）
対象や範囲が、指示から一意に決まらない指示。
境界の侵害（action-boundary violation）
意図した対象や範囲を超えて操作すること。
ハーネス（実行環境）
モデルを動かして、ツールの実行や確認の流れを管理する枠組み。
