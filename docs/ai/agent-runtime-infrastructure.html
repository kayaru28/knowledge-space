AIエージェントの実行基盤が動いている：隔離、起動の速さ、状態の保存、データベース

9月28日から10月9日までに出た5件の公式発表（Microsoft、Cloudflare、gVisor、Deno、Supabase）をもとに、エージェントを動かす基盤が、層ごとにどう変わっているかを図で整理する。

初回公開 2026-10-19 ／ 更新日 2026-10-19

ひとことで言うと

9月28日から10月9日までの間に、AIエージェントを動かす基盤に関する発表が5件ありました。隔離（Microsoft、gVisor）、起動と状態の保存（Cloudflare）、実行環境の統合（Deno が Cloudflare に合流）、データベース（Supabase が Turso を買収）と、層が違います。共通しているのは、「エージェントを安全に・速く・状態を持って動かす」ための部品が、次々に整ってきていることです。

実務で気をつけたいのは、移行の期限が示されたものがあることです。Cloudflare の旧 Container / Sandbox クラスの保守は2026年12月31日まで、Deno Deploy は約6か月後に終了、Deno ランタイムの開発は約1年後に終わります。

発表ごとの要点

Microsoft Execution Containers（MXC）

  • 公開：10/7（Windows Developer Blog）
  • ポリシーはエージェントの制御外にあり、エージェント自身が追加のアクセス権を得ることはできない
  • コンテナ：プロセス（Windows 11、macOS、Linux）、セッション・WSL（Windows 11）、MicroVM（Windows 11、Linux。実験的）
  • 制御できる対象：コンテナ、プロセス、ファイルシステム、ネットワーク、ユーザーインターフェース
  • モード：Enforcement（適用）、Learning（未許可をブロックして記録）、Permissive（記録して許可）
  • 対応：Copilot、OpenClaw、Codex、Replit、LM Studio、Unsloth AI。NVIDIA は OpenShell を統合。Claude Code などは対応予定

Cloudflare Containers

  • 公開：9/30
  • 実行時に、サンドボックスごとのイメージとインスタンスをコードから選べる
  • ファイルシステムのスナップショット（公開ベータ）。作業の中断時に保存し、再開時に復元する
  • 新機能は ctx.container のみ。旧クラスは 12/31 まで保守
  • 料金、上限、一般提供の時期は記載なし

gVisor

  • 公開：10/2（申請 9/7、審査 9/22、承認 9/28）
  • コンテナと仮想マシンの中間に位置するサンドボックス型のコンテナランタイム
  • 数週間以内にメンテナ制へ、数か月以内に組織単位の投票へ。リポジトリは google 組織の外へ
  • 短期の影響は「Not much」（公式）

Deno が Cloudflare に合流

  • 公開：10/9
  • workerd と celld を統合し、Workers と Durable Objects のセルフホストを簡素化する
  • Durable Objects に注目する理由：安価なサーバーレス実行、永続的な状態、WebSocket、高水準の JavaScript インターフェースがあり、エージェントの実行基盤に有用だとされる
  • JSR は継続。rusty_v8 は workerd への統合を目指す
  • 取引条件の記載はない

Supabase が Turso を買収

  • 公開：10/2
  • Turso は SQLite を Rust で作り直している。1台のサーバーで「数百万」のデータベースを管理でき、使われないものは停止する
  • エージェントがファイルを作るように、低コストでデータベースを作れる環境を目指す
  • Supabase は現在、週に100万以上のデータベースを立ち上げている
  • 既存ユーザーに変更はない。完了時期、条件、金額は記載なし
