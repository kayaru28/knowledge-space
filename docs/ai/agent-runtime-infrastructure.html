AIエージェントの実行基盤が動いている：隔離、起動の速さ、状態の保存、データベース

9月28日から10月9日までに出た5件の公式発表（Microsoft、Cloudflare、gVisor、Deno、Supabase）をもとに、エージェントを動かす基盤が、層ごとにどう変わっているかを図で整理する。10月21日に、使う側の設計例としてデジタル庁の「源内」を追加。

初回公開 2026-10-19 ／ 更新日 2026-10-21

ひとことで言うと

9月28日から10月9日までの間に、AIエージェントを動かす基盤に関する発表が5件ありました。隔離（Microsoft、gVisor）、起動と状態の保存（Cloudflare）、実行環境の統合（Deno が Cloudflare に合流）、データベース（Supabase が Turso を買収）と、層が違います。共通しているのは、「エージェントを安全に・速く・状態を持って動かす」ための部品が、次々に整ってきていることです。

実務で気をつけたいのは、移行の期限が示されたものがあることです。Cloudflare の旧 Container / Sandbox クラスの保守は2026年12月31日まで、Deno Deploy は約6か月後に終了、Deno ランタイムの開発は約1年後に終わります。

10月21日追記：使う側の例として、デジタル庁が政府職員約18万人向けの「ガバメントAI 源内」で AIエージェントの利用環境を始め、外への送信を止めるなどの制限と、立場ごとの決まり（源内基準）を公表しました。

発表ごとの要点

Microsoft Execution Containers（MXC）

  • 公開：10/7（Windows Developer Blog）
  • ポリシーはエージェントの制御外にあり、エージェント自身が追加のアクセス権を得ることはできない
  • コンテナ：プロセス（Windows 11、macOS、Linux）、セッション・WSL（Windows 11）、MicroVM（Windows 11、Linux。実験的）
  • 制御できる対象：コンテナ、プロセス、ファイルシステム、ネットワーク、ユーザーインターフェース
  • モード：Enforcement（適用）、Learning（未許可をブロックして記録）、Permissive（記録して許可）
  • 対応：Copilot、OpenClaw、Codex、Replit、LM Studio、Unsloth AI。NVIDIA は OpenShell を統合。Claude Code などは対応予定

Cloudflare Containers

  • 公開：9/30
  • 実行時に、サンドボックスごとのイメージとインスタンスをコードから選べる
  • ファイルシステムのスナップショット（公開ベータ）。作業の中断時に保存し、再開時に復元する
  • 新機能は ctx.container のみ。旧クラスは 12/31 まで保守
  • 料金、上限、一般提供の時期は記載なし

gVisor

  • 公開：10/2（申請 9/7、審査 9/22、承認 9/28）
  • コンテナと仮想マシンの中間に位置するサンドボックス型のコンテナランタイム
  • 数週間以内にメンテナ制へ、数か月以内に組織単位の投票へ。リポジトリは google 組織の外へ
  • 短期の影響は「Not much」（公式）

Deno が Cloudflare に合流

  • 公開：10/9
  • workerd と celld を統合し、Workers と Durable Objects のセルフホストを簡素化する
  • Durable Objects に注目する理由：安価なサーバーレス実行、永続的な状態、WebSocket、高水準の JavaScript インターフェースがあり、エージェントの実行基盤に有用だとされる
  • JSR は継続。rusty_v8 は workerd への統合を目指す
  • 取引条件の記載はない

Supabase が Turso を買収

  • 公開：10/2
  • Turso は SQLite を Rust で作り直している。1台のサーバーで「数百万」のデータベースを管理でき、使われないものは停止する
  • エージェントがファイルを作るように、低コストでデータベースを作れる環境を目指す
  • Supabase は現在、週に100万以上のデータベースを立ち上げている
  • 既存ユーザーに変更はない。完了時期、条件、金額は記載なし

使う側の設計例：デジタル庁の「源内」

10月21日の追記です。ここまでの5件は、基盤を作る側の発表でした。10月20日、使う側の例として、デジタル庁が、政府職員約18万人が使える AI 基盤「ガバメントAI 源内」で、AIエージェントの利用環境の提供を始め、あわせて「ガバメントAI 源内 ガバナンス・セキュリティ・セーフティに関する基準」（源内基準、第1版）を公表しました。AIセーフティ・インスティテュート（AISI）の協力を得て作られ、利用者、管理者、開発者の立場ごとに、責務と守ることを定めています。

源内基準（第1版、令和8年10月時点）より。2つの環境の制限の違い
面エージェントチャット源内工房
使い始め留意事項を確認して同意した利用者が使える。10月20日から各府省庁へ順次導入初期状態では使えない。一定の水準を満たすと確認された職員の申請に基づき、管理者が権限を与える。令和8年12月ごろまでの導入を目指す
ファイル利用者ごとの領域（マイドライブ）の中だけ。AI が上書き・削除できるのは、AI が作ったファイルだけで、原本は書き換えられない利用者が変えられる設定は、許された範囲だけ。共通の設定は、起動のたびに所定の内容で上書きされる
外部との通信Web 検索はガバメントクラウドの中で完結し、取得元のサイトへは通信しない。管理されていない API や MCP サーバーへは直接アクセスできない外部へのデータの送信（POST、PUT など）は遮断。取得（GET）は許可し、通信先・量・日時を記録
実行アップロードしただけで実行ファイルが動くことはない。ツールとコードは、決められた環境と権限の範囲で動く。利用者のパソコンは直接操作できないネットワーク層の防御は回避できない構成
記録と停止源内全体の決まりとして、入力の内容やファイル、出力などを、必要な範囲で記録し、一定期間保存する入出力や外部との通信などを、改ざんを防ぐ形で記録。問題があれば利用権限を止められる

想定しているリスク

誤った判断の連続実行、作業ファイルの誤った消去や改変、権限を超えた処理、機密情報の不適切な扱いなどを挙げています。

利用者に求めること

重要な処理の前に確認または承認する。ファイルの更新や削除など、影響の大きい処理は、利用者が実行するかを判断する。処理が目的や権限の範囲を外れていないかを監督する。

今後

エージェントチャットと源内工房は、「源内OSS Ver.2.0」として、2027年2月ごろに、商用利用もできるライセンスで公開する予定です。

筆者の整理：基盤側の「隔離」の部品（MXC、gVisor、Cloudflare のサンドボックスなど）に対して、源内は、使う側が「どこまで許すか」を、ファイル、通信、実行、記録、人の承認の面で決めた例です。とくに、外への送信を止めて、取得は許して記録する、という線の引き方は具体的です。

用語メモ

サンドボックス
信頼できないプログラムを、外部に影響を与えないよう隔離して動かす仕組み。
Durable Objects
Cloudflare の、状態を持つ分散シングルトン。
スナップショット
ある時点の状態を保存し、あとで復元できるようにしたもの。
CNCF
Cloud Native Computing Foundation。Kubernetes などを管理する団体。
SQLite
ファイル1つで動く軽量なデータベース。
パーセンタイル
値を小さい順に並べたとき、下から何％の位置にあるかを示す指標。99パーセンタイルは、遅い側の1％の境目。
MCP サーバー
AI が外部のツールやデータを使うための窓口になるサーバー（Model Context Protocol）。
GET と POST
Web の通信の種類。GET は情報を取りに行く、POST や PUT は情報を送り出す。
