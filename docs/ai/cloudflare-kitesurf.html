Cloudflare の「Kitesurf」：AI エージェント向けに Workers の上だけで動くブラウザが、8月の発表から11月にオープンソースになった

Cloudflare が2026年8月に発表し、11月にオープンソース化した、AI エージェント専用のブラウザ「Kitesurf」の設計、公式が示す性能と得意・不得意、オープンソース化の条件を、Cloudflare のブログと変更履歴をもとに整理する。

初回公開 2026-11-20 ／ 更新日 2026-11-20

ひとことで言うと

Cloudflare は2026年8月6日、AI エージェント向けに作った新しいブラウザ「Kitesurf」を発表しました。Cloudflare Workers の上だけで動き、Browser Run で、ベータの間は無料で使えます。11月12日と13日には、GitHub でオープンソース（Apache 2.0）として公開したと発表しました。

Cloudflare は、スクリーンショットや HTML の抽出といった作業で、Chromium より CPU とメモリの消費が3倍から7倍少ない一方、完了までの時間は約1.7倍長いと、自社の測定で書いています。動画の再生や WebGL などは、まだ対応していません。

なぜ作ったか、どう作ったか（8月のブログ）

  • 狙い：Chromium は人のために作られており、エージェントには不要なオーバーヘッドが大きい。メモリと計算が重く、エージェントごとに1つ持たせるのは費用が高い。エージェントに必要なのは、トークン数、コンテキストの長さ、拡張性、性能、費用で、タブやテーマ、拡張機能、画素単位の描画ではない、と書く。
  • 脅威の想定が違う：プロンプトインジェクションとツールの安全性を優先する。すべてのページの読み込みを、信頼できない入力として扱い、セッションはいつも新しく始める。
  • 状態を持たない：状態は、障害を高くつくものにする。状態のない部品は、使い捨てで、並列にしやすい。可能な部品は、すべてステートレスにした。
  • 実装：Rust を、WebAssembly に直接コンパイルして使う。AI のエージェントの力を借りて、移植を進め、Web Platform Tests（W3C の標準への適合を測るテスト群）を、成功の基準にした。実在のサイトでの統合テストと、見た目の回帰テストも組み合わせた。

3つの部品

Engine

唯一、外に公開される部品。Chrome DevTools Protocol（CDP）の WebSocket と HTTP の API を扱い、セッションの状態を保存する。Puppeteer、Playwright などの CDP の道具が、そのまま使える。ほかの部品は、ステートレス

PageScript

ページごと（別プロセスの iframe を含む）に、Dynamic Workers で、長く動く分離環境を立ち上げ、HTML の解析と、JavaScript、WebAssembly の実行を行う。HTML と CSS の解析には、Rust 製の Blitz と Stylo の一部を使う。eval は、Rust 製の Boa JS で実行する（Workers が eval に対応するまでの措置）

PageRenderer

計算されたページの内容から、画素を生成する。フォントや画像を静的アセットから取り、画像のバッファにして、Engine に返す。状態は持たず、失敗したら、Engine が作り直せる

ネットワークへのアクセスは、SandboxOutbound という1つの部品だけが行い、ほかの部品は、直接触れません。CORS の適用、ヘッダの付与、応答のフィルター、ページごとの Cookie の分離をここで行い、方針に反するものには 403 を返す、と書いています。

Cloudflare は、時間で Chromium に負ける理由を、「すでにそのページを見た JIT は、冷えたソフトウェアの描画に勝つため」と説明し、差の多くは、ラスタライズと JPEG/PNG の符号化にあると書いています。Web Platform Tests は、約21.5万件を通過し、毎週数百件ずつ増えている、と書いています（8月時点）。

得意なことと、まだできないこと

  • 向いている：ページを描画する必要はあるが、完全な Chromium の機能や、画素単位の一致までは要らない AI エージェント。ページからの内容の抽出、PDF やスクリーンショットの生成といった、1回で終わる作業（対応するサイトに限る）。
  • できない（8月時点）：動画の再生、WebGL の描画、実際の TLS のフィンガープリントを使った、ボット対策のチャレンジへの応答、状態を保つ必要のある、10分間の認証つきセッション。これらは、Chromium を使う Browser Run の既定を使う、と書く。
  • 対応が確認されたページ：TodoMVC（複数の実装）、Wikipedia、Hacker News、Cloudflare のブログ、Cloudflare のダッシュボードの多く。
  • 使い方：Browser Run の CDP の接続先と、クイックアクションに、パラメーター「browser=kitesurf」を足すだけで使える。公開のプレイグラウンド（Chrome DevTools つき）でも試せる。

オープンソース化（11月）

  • 条件：GitHub で、Apache 2.0 ライセンス。コードを読み、手元で動かし、変更し、自分の Cloudflare の Workers に配備できる。
  • 構成：Blitz（HTML の解析、DOM、レイアウト、描画）、Stylo（CSS）、Boa（WebAssembly 内の JavaScript。Dynamic Workers で動かせないときの最後の手段）、Linebender のライブラリ（文字の配置と2D 描画）、Krilla（PDF の出力）の上に作られている。各プロジェクトは、それぞれのライセンスを保つ。
  • 必要なもの：自分の Cloudflare で動かすには、Dynamic Workers を使うため、Workers の有料プランが必要。手元の開発は、wrangler dev で動かす。
  • 認証：Kitesurf には、認証の機能がない。変更履歴は、Cloudflare Access などの認証の層で、配備を守るよう求めている。
  • 状態：実験的で、開発が活発。互換性、信頼性、効率を優先する。貢献は歓迎だが、レビューの余力は限られ、まず Issue を出し、メンテナーの承認（vouch）を得てから、プルリクエストを出す、と書く。

読むときの注意（筆者の整理）

  • 性能の数値は、Cloudflare が自社の環境で、8月に測ったものです。第三者の測定ではなく、その後の更新で変わっている可能性があります。
  • 「完了までの時間は長い」点は、公式が自ら書いている不利な点です。費用を決めるのは、CPU とメモリだ、というのが、公式の主張です。
  • このまとめは、製品の優劣や、導入の勧めは扱いません。

用語メモ

Cloudflare Workers
Cloudflare のネットワーク上で、プログラムを動かす仕組み。分離された環境（isolate）で動く。
Dynamic Workers
実行のときに、分離された Workers を作れる仕組み。Kitesurf は、ページごとの環境に使う。
Browser Run
Cloudflare のヘッドレスブラウザの API の製品。
CDP（Chrome DevTools Protocol）
ブラウザを外から操作するための通信の約束。Puppeteer などが使う。
Web Platform Tests
ブラウザが Web の標準に合っているかを測る、共通のテスト群。
WebMCP
Web のページを、エージェント向けの道具として公開する仕組み（9月の更新で対応したと書かれている。詳細は未確認）。
