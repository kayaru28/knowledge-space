OpenAI の最新モデルが、COBOL などの学習データの少ない言語で大きく伸びた：MultiLangBench と COBOL 移行の評価

OpenAI が2026年10月19日に公表した、COBOL、Fortran、Visual Basic、OCaml など学習データの少ない言語でのコーディング能力の向上について、2つの評価（MultiLangBench、COBOL の移行）の結果と、読むときの注意を、公式の記事から整理する。

初回公開 2026-10-27 ／ 更新日 2026-10-27

ひとことで言うと

OpenAI は2026年10月19日に、COBOL、Fortran、Visual Basic、OCaml など、AI が学習に使えるコードやドキュメントが少ない言語で、最新のモデルの開発・移行の能力が大きく上がったと発表しました。自社で作った2つの評価の結果も示しています。

20言語でデータベースを一から作らせる評価では、GPT-6 Astra の平均合格率は87.4%（GPT-5.6 Sol は26.8%）。COBOL を他の言語に移行する評価では、GPT-6.1 Sol が推論量を低くしても86.6%（GPT-5.6 Sol は5.4%）、推論量を増やすと97.9%でした。ただし、評価は OpenAI 自身が作ったもので、比較の相手も自社の前のモデルだけです。OpenAI も、本番への適用には専門家のレビューが必要としています。

なぜ、学習データの少ない言語なのか

  • OpenAI は、こうした言語は Python や JavaScript に比べて学習に使えるコードやドキュメントが少ない一方で、世界の重要な基盤を支えている、と説明している。
  • COBOL は、オンラインバンキングのシステムの40%超、対面のクレジットカード取引の80%、ATM 取引の95%を支えている、と書いている。Fortran は、天気予報や原子炉の安全解析に使われている。
  • きっかけは、開発者や企業の顧客から、コーディングのモデルがこうした言語を苦手としているという声が寄せられたこと。
  • 保守や移行が難しい理由として、ドキュメントが不完全なこと、最初の開発者が退職していること、重要な業務ルールがコードの中にしか残っていないことを挙げている。バグの修正でも別の言語への移行でも、システムが前提としている動作を維持する必要がある。

2つの評価

MultiLangBench：新しいソフトウェアを作る力

20種類のプログラミング言語それぞれで、SQLite 互換のデータベースエンジンを一から作らせる。コードベースの整理、状態管理、エラー処理を行い、既存の機能を保ったまま新しい機能を足す必要がある。言語を問わず同じテストを使うため、データベースのファイルを共通のインターフェースにした。SQLite の既存のテストを、この形に合わせて調整した。テストの合格率と API の費用を報告する。評価の環境とテストを、各言語の結果とともに GitHub で公開するとしている

COBOL の移行：既存のソフトウェアの動作を保つ力

COBOL のプログラムを、C++、Java、Kotlin、Python、Rust のいずれかに移行させ、元と同じ動作を保てるかを調べる。出力がバイト単位で完全に一致することを求める、非公開のテストを使い、すべてに合格した場合だけ成功とする。例として、COBOL の固定小数点演算は、丸めを明示しなければ、余分な小数桁を切り捨てる。移行後に値を丸めてしまうと、エラーなく動いても、金額の計算結果が変わりうる

  • GPT-6 Astra は、評価した全言語で改善し、20言語中19言語で83%を超えた。COBOL は72%で、最も難しい言語のままだった。
  • GPT-6 Luna（低コストの選択肢）も、全言語で GPT-5.6 Sol を上回った。サンプルあたりの推定 API 費用は平均0.77ドルで、GPT-5.6 Sol の3.48ドルより約78%低い。
  • COBOL の移行：推論量を低くした GPT-6.1 Sol が86.6%の正解率（同じ設定の GPT-5.6 Sol は5.4%）。API の費用は GPT-5.6 Sol より39%低い。推論量を増やすと97.9%に達し、この評価では上限に近い。

読むときの注意

  • 評価は OpenAI 自身が作ったもの：MultiLangBench も COBOL の移行の評価も、同社が開発した。比較の相手は、同社の前のモデル（GPT-5.6 Sol）で、他社のモデルとの比較は示されていない。
  • 移行の評価のテストは非公開：結果の再現や、テストの内容の確認は、外からはできない。MultiLangBench は、環境とテストを公開するとされている。
  • 「正解」の意味：移行の評価の成功は、非公開のテストの出力がバイト単位で一致することで、実際の業務システムでの安全性の保証ではない。OpenAI も、本番のソフトウェアに適用するには、専門家によるレビューと、システムの業務ルールや依存関係に照らしたテストが必要としている。
  • 推論量の違い：数字は、推論量の設定（最大、低いなど）によって異なる。表の GPT-6 Astra と GPT-6 Luna は最大の設定。費用の比較も、設定と条件に依存する。
  • OpenAI は、使っているチームに、API で最新のモデルを試して、どこでつまずくか、どの言語やワークフローに注力すべきか、フィードバックを寄せるよう求めている。

見方（筆者の整理）

  • 数字の大きな伸び（5.4%から86.6%など）は、前のモデルとの比較で、2つの評価に限られる。実際の古いシステムの移行で同じ水準が出るかは、この発表からは分からない。
  • 移行で問題になるのは、動くことより、動作が元と同じことだ。丸めの例のように、エラーなく動いて金額が変わる失敗は、見つけにくい。非公開テストでバイト単位の一致を見る評価は、この点を意識した作りだが、本番での検証の代わりにはならない。
  • COBOL は、20言語の中で最も難しいままだった。伸びたとはいえ、他の言語との差は残っている。
