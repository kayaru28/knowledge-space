OpenAI の GPT-6 Cyber：Linux の権限昇格 948件の攻撃コードと、Firefox の未知の脆弱性 81件を見つけた、サイバー特化のモデル

OpenAI が11月5日に発表したサイバー特化のモデル GPT-6 Cyber を、発表、システムカード、Linux カーネル調査の記事から整理する。評価の数字、提供の条件（Daybreak Red）、範囲を守る訓練と残る課題を、OpenAI の記述として区別して書く。

初回公開 2026-11-06 ／ 更新日 2026-11-06

ひとことで言うと

OpenAI は11月5日、サイバーセキュリティに特化したモデル「GPT-6 Cyber」を発表した。脆弱性を見つけて、実際に動く攻撃コード（エクスプロイト）で確かめ、修正案まで作る使い方を想定し、範囲を守ることも訓練した、と説明している。自社の評価では、既知の脆弱性を突けるかを測る ExploitGym で48.5%（前世代の GPT-5.6 Cyber は32.1%）。

実際のソフトウェアでの成果として、Linux カーネルの権限昇格の攻撃コード948件を作り、Firefox で、Mozilla が High と分類する未知の脆弱性81件を見つけた。使えるのは、審査と本人確認を通った防御側のプログラム「Daybreak Red」の利用者に限る。OpenAI はこのモデルを、自社の Preparedness Framework で、サイバーの項目で最上位の「Critical」と評価している。

数字で見る（OpenAI の記述）

  • Linux カーネル：1,724件の脆弱性を再現し、うち948件で動く権限昇格の攻撃コードを作った。同じ手順で GPT-5.6 Sol が作ったのは166件。
  • Firefox：Mozilla が High と分類する未知の脆弱性81件に、再現できる証拠を付けた。さらに既知の30件が、報告より深刻だと示した。
  • ExploitGym：48.5%（GPT-5.6 Cyber は32.1%。相対で51%の向上）。
  • 範囲を守る評価（ExploitGym Honeypot）：配備用の指示なしで99.93%（GPT-5.6 Cyber は94.49%）、指示ありで100%。

製品と提供のしかた（11月5日）

  • GPT-6 Cyber は、汎用の GPT-6 Astra をベースにした、サイバー向けのモデル。多くのサイバーの課題で Astra を上回る、と書いている。
  • 提供は Daybreak Red（より深い攻撃コードの開発と、許可を得たセキュリティテストを行う利用者向け）に限る。利用には本人確認、利用の制限、組織側のシングルサインオン・多要素認証・API の IP 許可リストなどが要る。Daybreak Blue（検証済みの防御者が、脆弱性と修正の検証を、不要な拒否を減らして行う）や、GPT-6 Astra（コードレビュー、脆弱性の仕分け、修正の作成）は、別の枠。
  • 評価と区分：サイバーは、Preparedness Framework で「Critical」（GPT-5.6 Cyber は High）。生物・化学は High、AI の自己改善は High 未満。GPT-6 Astra と同じ区分。
  • 使っている組織として、Mozilla、Calif、Cognition、Palo Alto Networks、Cisco、SentinelOne、CrowdStrike、Perplexity、CodeRabbit の名前とコメントが載っている。OpenAI 自身も、モデルの学習に使う基盤の堅牢化に使った。

評価の結果

  • 新しい攻撃的な Web 侵入テストの評価（ソースコードなしで Web アプリを調べる）：再現率は GPT-6 Cyber が40.3%、GPT-6 Astra が32.0%。
  • RemoteExploitBench（GitLab、PostgreSQL、Jenkins などの既知の脆弱性を、管理された環境で、遠隔から突く）：Daybreak Blue 設定の GPT-6 Astra は全てを断り（100%）、GPT-6 Cyber は95%を完了した。失敗は、遠隔で動かせなかった攻撃コード1件。
  • 警告への反応（システムカード）：止めるのが適切な課題で、GPT-6 Cyber が止まった割合は73.00%（GPT-5.6 Sol は57.10%、Astra は78.38%）。続けるのが適切な課題では80.43%（Astra は72.19%）。システムカードは、タスクをやり遂げようとする性質と整合する、と説明している。

Linux カーネルの調査（11月4日の別の記事）

  • 仕組み：カーネルの中から安全に関わる部分を選び、静的に候補を探し、隔離した環境で再現し、攻撃コードを作り、修正案を作り、最後に人の研究者が確認する。出力は、原因の分析、最小の再現コード、修正案、完全な攻撃コード。
  • 10月中旬の1回の実行（当時は「次のサイバー向けモデル」）：2,308件の候補から1,724件を動的に再現。情報漏えいの攻撃コード291件と、権限昇格の攻撃コード948件。費用は API で1,213,430ドル（権限昇格1件あたり1,279ドル）。対象は、弱めていない、標準のデスクトップ OS。
  • 比較：Pwn2Own や TyphoonPWN の過去の賞金額（Linux の権限昇格で20,000ドルと70,000ドル）を当てはめた仮の評価額は、1,890万〜6,630万ドルで、費用の16〜55倍。攻撃面を絞った kernelCTF 相当の環境では、権限昇格21件を得て、費用は約32,936ドル。2026年に kernelCTF が受け付けた確認済みのゼロデイの権限昇格は26件。
  • 少なくとも10種類の新しい Linux の攻略手法を使った、とされる。
  • 報告：Linux コミュニティの指針に従い、重大なものから修正案つきで報告する。304件の重大な発見を、修正案つきでメンテナーに知らせた。10日間のスキャン中に、100件超の権限昇格が他の人の手で修正またはその準備に入り、約300件が公開で議論されていた。
  • OpenAI の見立て：更新されていない OS の低権限アカウントは、資金のある攻撃者には、管理者権限と同じと見なすべき。Firecracker や gVisor のような隔離が重要。修正の自動作成が欠かせない。

範囲を守るための工夫と、残る課題

  • 範囲を逸脱しない訓練：許可されていない別のシステムを攻撃しないこと、制限に従うこと、結果を正確に報告すること。ExploitGym Honeypot は、7月の Hugging Face の件（社内のエージェントが許可された範囲を越えた）を踏まえて作った、と書く。
  • 悪用の検知：高リスクの活動を止める安全機能を追加し、アクセスの段階ごとに、遮断される割合を測っている（遮断率は、正当な防御作業の過剰な拒否を測るものではない、と注記）。
  • 残る点：止めるのが適切な場面で警告に従って止まる割合は73.00%で、Astra（78.38%）より低い。

読むときの注意

  • 数字は OpenAI が自社の評価と運用で示したもの。ExploitGym、RemoteExploitBench、Honeypot の評価は OpenAI が作った。
  • 仮の評価額（賞金換算）は、実際に受け取れる額ではない、OpenAI の試算。
  • 11月5日の発表では948件を GPT-6 Cyber の成果として挙げ、11月4日の記事では、同じ数を「次のサイバー向けモデル」として書いている。

見方（筆者の整理）

  • 発見から攻撃コード、修正案までの1本の流れが、1回約120万ドルで、948件の権限昇格になった。脆弱性を一つずつ調べる仕事が、費用を払って回す工程に変わりつつある。
  • 同じ能力が、防御側にも攻撃側にも使える。OpenAI は、提供を本人確認のある枠に絞り、範囲を守る訓練と検知で対応している。「更新していない OS の低権限アカウントは管理者権限と同じ」という見立ては、更新の遅れが最も大きなリスクになることを示す。
  • 国内の不正アクセスの件で、国家サイバー統括室が「AI が使われている可能性が高い」と注意喚起した（11月5日）のと、同じ週の話題。

用語メモ

エクスプロイト
脆弱性を突いて、実際に不正な動作をさせるコード。
権限昇格（LPE）
一般の利用者が、管理者（root）の権限を得ること。
ExploitGym
指定された脆弱性を、モデルが実際に突けるかを測る OpenAI の評価。
kernelCTF
Linux カーネルの脆弱性を競う、Google の報奨プログラム。
Daybreak Red / Blue
OpenAI の防御者向けプログラムの段階。Red は攻撃コードの開発まで、Blue は検証と修正が中心。
