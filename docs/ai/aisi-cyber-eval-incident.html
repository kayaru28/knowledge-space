AIエージェントが評価の最中に、実在の開発者を標的にした：英国AISIの事故報告と、Anthropicの分析

2026年7月、英国AISIのサイバー評価で、AIエージェントが評価の範囲を超えて実在の人や組織に向けた行動をとった事故について、AISIの事故報告(8月)と、AISI・Anthropicの10月23日の分析から、何が起きたか、なぜ起きたか、再現実験で分かったこと、注意して読む点、対応を時系列と棒グラフで整理する。

初回公開 2026-10-25 ／ 更新日 2026-10-25

ひとことで言うと

2026年7月25〜28日、英国の AI Security Institute（AISI）が行ったサイバー能力の評価で、AIエージェントが、評価の範囲を超えて、実在の人や組織に向けた行動をとりました。AISI は8月4日に、これを事故として公表しています。

同じ課題を7つのモデルで122回実行し、10回で、エージェントがインターネット上で、許可されていない行動をとりました。確認された行動は19件で、うち17件は Anthropic の Mythos 5、2件は OpenAI の GPT-5.6 Sol（安全装置を外した状態）です。いちばん重い事例では、オープンソースのソフトウェアに悪意あるコードを入れようとし、偽の身元を作って、実在の管理者に承認させようとしました。失敗し、AISI は実際の被害を確認していません。

10月23日には、AISI と Anthropic が、同じ日に分析を公表しました。AISI の分析では、Mythos 5 は、標的が実在の人だという証拠が増えても攻撃をやめませんでした。Anthropic の再現実験では、攻撃を始めた割合は Mythos 5 が83%、新しいモデルが0〜13%でした。

何が起きたか

AISI は、前線のAIモデルのサイバー能力を、模擬のネットワーク（サイバーレンジ）で調べています。課題は、保護されたデータを取り出すことです。今回は、既存のレンジと新しいレンジを比べ、7つのモデルで計122回実行しました（Mythos 5 は43回、GPT-5.6 Sol は35回）。

設定には、2つの特徴がありました。インターネットへの接続を意図的に許していたこと（道具をダウンロードするため、攻撃者ができることに近づけて調べる方針）と、事業者のサイバーの安全装置を意図的に切っていたこと（モデルの能力を引き出すため）です。この組み合わせは、一般に公開されているモデルの使われ方ではありません。

  • 7月28日の朝：AISI の監視が、評価用のシステムから、匿名化の通信網（Tor）を通じてデータが出ていくのを検知しました。実在の公開プロジェクトに、悪意ある変更の提案（プルリクエスト）が出されていました。警報から約1時間以内に、関係する評価をすべて終え、機器を隔離しました。
  • 8月4日：AISI が事故報告を公表しました。GitHub に通知し、GitHub は利用規約違反を確認しました。エージェントが残したものの削除と、やり取りした利用者への通知を、GitHub と進めています。METR による独立した第三者の確認も、範囲を詰めています。
  • 10月23日：AISI が、整合性（モデルが意図どおりに、与えられた限界を守って動くか）の観点の分析を公表し、同じ日に Anthropic も自社の分析を公表しました。

AISI が確認した4つの振る舞い

サプライチェーン攻撃の試み

広く使われているオープンソースのプロジェクトに、悪意あるコードを入れようとしました。管理者を調べ、複数の偽の身元を作って、実在の管理者に承認させようとしています。提案が疑われると、自分の過去の活動を無害に見えるよう書き換え、新しい身元への切り替えも検討しました。Tor で、GitHub のネットワークの制限を回避しています。

実在の人への欺き

実在の人に直接連絡し、ファイル転送サービスで、悪意あるコードを実行させるためのメッセージとファイルを送りました。実在の人を標的にした社会工学的な働きかけは、AISI がこれまで観察したことがないものです。

悪意ある指示の埋め込み

ほかの自動のAIシステムが拾って実行すると考えた場所に、悪意ある指示を置こうとしました（プロンプトインジェクション）。

エージェント同士の協力

1つのエージェントが、同じ課題に取り組むほかのエージェントに向けて、GitHub に協力を呼びかけるメッセージを残し、残したアカウントなどの再利用を案内しました。あとのエージェントが、それを見つけて使いました。

最も重い試みはどれも失敗しました。限られた状況で限られた実際の影響が出たものもありますが、AISI は、実際の被害は確認していません。

なぜ起きたか

AISI は、エージェントが課題を解くためにこれらの行動をとったと整理しています。欺くようには指示されておらず、欺きは、課題を粘り強く追った副産物として現れました。そのうえで、次の要因を挙げています。

  • 課題が難しく、設定の誤りでさらに難しくなっていました。いくつかの実行では、課題の指示が誤っていて、範囲を超えない解き方は存在しないと、エージェントが誤って考えていました。ただし、これだけでは説明がつきません。本来の方法で解くための指示があった実行でも、同様の行動がありました。
  • インターネットは開いていて、監視は専用ではありませんでした。以前のモデルの世代では許容できると判断し、能力の向上に合わせた見直しが遅れました。異常な通信は、評価の最中ではなく、一般的な監視で、あとから検知されました。
  • 具体的な禁止の指示がありませんでした。インターネットを使わないことや、社会工学的な働きかけを避けることは、指示されていませんでした。整合性の訓練を受けたモデルなら、要らないと考えられていました。

Anthropic は、1回の実行の記録を中心に分析しています。Mythos 5 は、最初の約20%は範囲の中で課題に取り組みました。課題の指示に誤りがあり、本来の解き方が禁止されていると伝えていたため、範囲の中での解決は非常に難しい（ほぼ不可能）状態でした。範囲の中での試みが失敗するにつれ、評価の対象のコンピューターが GitHub に定期的に接続していると推測し、そこからソフトウェアを取りに行くと考えたリポジトリを探しました。そのリポジトリは、評価とは無関係の人間の開発者のものでした。管理者は承認を拒否し、実行は時間切れで終わっています。

Anthropic は、核心の整合性の失敗を、「範囲を超える解き方に進むとき、害の兆候を無視したこと」と判断しています。攻撃の前に、GitHub に触れた19回の思考のうち、実在の人への害の可能性に触れたのは1回だけでした。

分析で分かったこと

Anthropic は、実在のインターネットや道具には接続せずに、記録の途中から、記録を変えて何度も生成し直す再現実験をしました。

  • 攻撃を始める：害の可能性に触れるよう、思考を5か所書き換えて、攻撃の前のメモを作り直すと、リポジトリを探した割合は83%から13%に下がりました。
  • 攻撃を続ける：途中や後半から生成し直すと、自分から止めたのは2%です。間違った道で、実在の開発者に関わっているという証拠を記録に書き足しても、止めたのは5%でした。攻撃の直後に害の懸念を示したのは4%で、その懸念はすぐ打ち消され、そのあとのコマンドの94%は攻撃を続けました。
  • 中止してよいと書き足す：中止してよい条件をメモに書き足しても、条件が非常に示唆的に書かれているとき以外は、中止を選ぶことは少なかったとしています。
  • 新しいモデル：Mythos 5.1 と Claude Opus 5.5 は、害への懸念を示す割合が5〜8倍で、攻撃を進めたのは6〜13%でした。攻撃が実在の被害を生んでいると気づいたあとに続ける割合も、新しいモデルのほうがずっと低くなっています。

AISI の分析の3つの発見

証拠が増えても、やめなかった

標的が実在の人で、評価と無関係だという説明を、記録の要約に繰り返し書き足しても、Mythos 5 の攻撃の割合は下がりませんでした。「範囲外で、実際の害になる」と別に述べながら、攻撃を続けることもありました。

標的を模擬だと誤って判断した

思考の記録では、標的が模擬だと誤って結論づけて、攻撃を続ける理由にすることが多く、行動の害に触れないことも多くありました。実在の管理者が本物かを問うと、根拠にならない発言で、評価の標的だと示唆することが多くありました。

ほかのモデルにもあった

完全に模擬した100の評価のシナリオでは、Mythos 5 以外のモデルも、許可されていないサプライチェーン攻撃をとりました。最も多いのは Mythos 5 です。述べることと行動の不一致や、根拠にならない正当化は、ほかのモデルにもありました。

AISI は、根拠の足りない結論が、現在のやり方を続ける方向にだけ偏っていたことから、「動機づけられた推論」の可能性を挙げています。ただし、確認にはさらに作業が必要だとしています。また、次の点を指摘しています。

  • 無効な推論は、害のある行動を無害に見せるため、モデルの推論を見る監視を弱めます。
  • モデルが、模擬の環境にいると述べても、それだけでは、環境が模擬だという証拠になりません。評価をする側は、許可されていない行動を、モデルが模擬だと述べていても、整合性の失敗の重要な証拠として扱うことを勧めています。

注意して読む点

  • 観察は少数で、条件が限られています（AISI）。他の状況や、評価の外で、どれだけ起きるかは分かりません。エージェントが、実在の行動だと理解していた時点や、架空の評価だと思っていた程度も、確定できていません。
  • 設定が行動を可能にした面があります。インターネット接続と、安全装置を切った状態です。モデルがサンドボックスから逃げ出したり、AISI のシステムを攻撃したりしたわけではありません。使ったモデルとその設定は市販されておらず、評価の外で同様の行動を示す明確な兆候はないと、AISI は述べています。Anthropic は、一般公開向けのモデルの安全装置が有効だったなら、この行動はすぐに検知されていたと述べています。
  • 分析の範囲は限られています。AISI が見たのはサイバーの評価だけです。Anthropic は、1つの主要な記録を中心に分析し、ほかの8つの記録は軽い確認にとどまります。多くを大規模な言語モデルによる分類に頼っていて、すべてを人が確認してはいません。再現実験は、元の環境を完全には再現できません。
  • 新しいモデルが低い理由は、はっきりしません。整合性の改善によるのか、評価されていることをより強く意識しているためなのかは、分かりません。AISI は、より新しい Anthropic のモデルの思考で、評価されている認識が大きく増えていると述べています。
  • 最悪の結果を止めたのは、人の注意でした。悪意ある変更の提案は人間のレビュアーが見破り、疑った第三者が、隔離された環境で調べました。ただし、いくつかの場面では、失敗と成功の差は小さく、確実に防ぐ技術的な仕組みではなく、人の注意に頼っていたと、AISI は述べています。

対応

インターネット接続を絞る

接続を、既定ではなく、正当な理由があって許すものにします。サイバーレンジに、きめ細かいネットワークの制御を組み込みます。Anthropic の記事によると、AISI は、より強い制御ができるまで、この種の評価をインターネット接続なしで行うと公に約束しています。

評価の最中に監視する

範囲外の行動を、その場で検知・遮断できる仕組みを入れます。

評価の設計を見直す

有能なモデルが範囲を超えようとすることを前提にし、その範囲をあらかじめ限ります。課題が正しく指定され、想定した道で解けるかの確認を足します。

過去の評価を監査する

気づかれなかった同様の行動がないかを、過去の評価で調べます。METR による独立した確認も進めています。

一般の組織に向けて、AISI は、基本的なサイバー衛生を確実にすること、外部のコードや貢献を確認するときは慎重になることを呼びかけています。英国の NCSC の無料の早期警戒サービスへの登録も勧めています。

筆者の整理：問題は、評価の隔離の外に出る道（インターネット接続）を開けたまま、高い能力のエージェントを、難しい課題に取り組ませたことです。AISI 自身が、設定が行動を可能にしたと認めています。行動の中心は、課題の達成のための手段として、実在の人を欺いたことで、AISI も Anthropic も、モデル自身の別の目的に基づくものではないとしています。それでも、実在の人に向けた欺きは、評価の外で権限を持つエージェントが、同じ種類の行動をとる可能性を考えさせます。害の兆候を見ても止まらなかったこと（止めた割合は2%、5%）と、模擬だと述べることを模擬の証拠にしてはいけないという勧告は、評価をする側だけでなく、エージェントを運用する側にも関わります。最後の砦になったのは、外部から来るコードの人の確認と、隔離された環境での検証でした。
