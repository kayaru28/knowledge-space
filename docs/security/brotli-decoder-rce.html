圧縮データを開くだけで、メモリが壊される：Brotli のデコーダーの欠陥（CVE-2026-111497）が、Node.js・Bun・Python に広がった

2026年10月21日に Node.js が修正した、圧縮の部品 Brotli のデコーダーの欠陥（CVE-2026-111497）について、何が壊れるのか、影響を受ける版と直った版、Bun と Python への広がり、備え方を、Node.js・Bun・Google の公式の発表から、年表と模式図で整理する。

初回公開 2026-10-25 ／ 更新日 2026-10-27

ひとことで言うと

2026年10月21日、Node.js は、同梱している圧縮の部品「Brotli」のデコーダー（圧縮データを元に戻す部分）に、細工されたデータを読み込ませると、メモリを壊され、最悪の場合は遠隔からコードを実行されるおそれがある欠陥（CVE-2026-111497）があるとして、修正版を出しました。

欠陥は、Node.js 自身ではなく、Google の Brotli のデコーダーにあります。影響を受けるのは Brotli 1.0.3〜1.2.0 で、同じ部品を同梱するソフトウェアは、それぞれ更新が必要です。Node.js のあとに、Bun（10月23日）や、Python のパッケージ（10月22日）も新しい版を出しました。

中身は、不正なデータを「形式の誤り」として拒否せず、「入力がまだ足りない」と扱ったため、デコーダーが8バイトの内部の領域に、入力を書き足し続けてしまうことです。Node.js は、報告者として「OpenAI Codex Security」（AI を使った脆弱性の調査道具）を挙げています。

Node.js の修正から、Bun のアドバイザリまで（10月21〜23日）

何が起きたか

  • 10月21日：Node.js が、26.x、24.x、22.x の各系統のセキュリティリリースを公開しました。この欠陥（深刻度は「high」）のほか、DNS や TLS のホスト名の検証の欠陥などの修正が入っています。同じリリースには、別のまとめで扱った、eMudhra の中間認証局の侵害に伴う証明書の更新も含まれます。同じ日に、Google の Brotli が 1.2.1 を公開し、この欠陥の修正を記載しました。
  • 10月22日：PyPI に、Python 向けの Brotli 1.2.1 と brotlicffi 1.2.1.0 が公開されました。
  • 10月23日：Bun が、同梱する Brotli の欠陥のアドバイザリ（深刻度は「High」）を公開しました。Bun 1.4.3 以前が、影響を受ける Brotli 1.2.0 を同梱していました。

何が壊れるのか

Node.js の説明によると、Brotli のデコーダーに、不正な「ブロックの切り替え」が入ったデータを渡すと、本来は形式の誤りとして止めるべきところを、「入力がまだ足りない」という一時的な状態として扱いました。そのため、ストリーム方式のデコーダーが、入力を内部の8バイトの領域に書き足し続け、領域の終わりを超えて書き込みました。

Bun の説明では、デコーダーにデータが渡る道は3つあります。fetch（既定で Brotli を受け入れ、Content-Encoding: br の応答を自動で展開します）、node:zlib、Brotli 形式の DecompressionStream です。fetch では、悪意のあるサーバーや、暗号化されていない通信の経路にいる攻撃者が、データを渡せます。Bun は、自分たちでは攻撃を試していないので、ほかのソフトウェアと影響を比べられないとしたうえで、コード実行のリスクとして扱うよう求めています。

10月25〜26日に広がった対応：JPCERT/CC、Microsoft の .NET、PHP の Windows 版（10月27日に追加）

JPCERT/CC の注意喚起（10月26日）

影響を受けるアプリが、細工された Brotli 形式のデータを展開すると、メモリの破損により、異常終了、メモリ上の情報の漏えい、任意のコード実行につながる可能性があるとして、速やかな対策の適用と侵害の有無の調査を求めた。対象の Brotli は、v1.2.0 から v1.2.1 より前、v1.1.0 から v1.1.1 より前、v1.0.3 から v1.0.10 より前。Google は緩和策を提供していないので、Brotli を組み込んだ製品の緩和策は、各開発者の情報を確認するよう案内している。この欠陥は、Node.js の公表に関連して「Node2Shell」と呼ばれていたが、原因は Brotli の C 言語実装にあり、HTTP 通信で使われるため複数の製品が影響を受けるとして、「HTTP2Shell」とも呼ばれている、と説明している。

Microsoft の .NET（10月25日〔世界標準時〕の定例外の更新）

.NET 8（8.0.33）、.NET 9（9.0.22）、.NET 10（10.0.14）と、.NET 11 の RC3 を公開。.NET の Brotli の使い方にバッファオーバーフローがあり、認証なしの攻撃者がプロセスのメモリを読み取ったり壊したりでき、情報漏えい、サービス拒否、権限昇格につながるおそれがある。影響を受けうるのは、ASP.NET Core のリクエストの展開、HttpClient の応答の自動展開、System.IO.Compression の Brotli の API を通して Brotli のデータを処理するアプリケーション。リクエストの展開と応答の自動展開は、既定では有効になっていない。.NET Framework は影響を受けない。自己完結型のアプリケーションは、更新したランタイムで作り直して公開し直す必要があり、コンテナは新しいイメージで作り直す。同じ更新に、Linux の .NET の配布物の所有者の問題（CVE-2026-114148）の修正と、10月13日の更新で十分に直っていなかった2件（CVE-2026-70197、CVE-2026-102870）の修正が含まれる。

PHP の Windows 版（10月26日）

PHP 8.5.12-1、8.4.27-1、8.3.36-1、8.2.35-1 を公開。Brotli 1.2.1 を含み、この欠陥を直している。Windows 版の PHP では、cURL 拡張で HTTP の応答の自動展開を有効にしたときに、問題のデコーダーに届く。既定では無効だが、アプリケーションや HTTP クライアントのライブラリが有効にすることがある。末尾の「-1」は、PHP のバージョンは変えず、依存ライブラリだけを更新して作り直した Windows 版であることを示す。

筆者の整理：同じ欠陥の修正が、Node.js、Bun、Python のパッケージに続いて、.NET と PHP の Windows 版にも広がった。展開の機能が「既定で有効か」は製品で違う。Bun の fetch は既定で Brotli を受け入れるが、.NET のリクエストの展開と応答の自動展開、PHP の cURL の自動展開は既定では無効。影響を受けるかは、設定やライブラリの使い方で決まる。公式の発表（JPCERT/CC、Microsoft、PHP）には、実際の悪用や被害の報告は書かれていない。

どう備えるか

更新する

Node.js は 22.23.4、24.22.1、26.12.1 に、Bun は 1.4.4 に更新します。Python のパッケージ Brotli と brotlicffi は、新しい版が出ているので、使っている環境に入っていないかを調べます。

.NET と PHP の Windows 版

.NET は 8.0.33、9.0.22、10.0.14（11 は RC3）に更新します。自己完結型のアプリケーションは、更新したランタイムで作り直して公開し直し、コンテナは新しいイメージで作り直します。Windows 版の PHP は、末尾が「-1」の新しいビルドに入れ替え、cURL 拡張で応答の自動展開を有効にしているかを確かめます。

作り直す

コンテナのイメージと、bun build --compile で作った実行ファイルは、中に部品を含んでいるため、作り直すまで影響が残ります。

同梱を調べる

自分のソフトウェアが、Brotli を直接の依存でも、間接の依存でも、含んでいないかを調べます。同梱する製品は、提供元の更新が必要です。

更新できない間（Bun）

fetch に decompress: false を渡すと、その要求では Brotli を受け入れず、応答を展開しません。信頼できないデータを、Brotli の機能に渡さないようにします。プロセス全体に効く回避策はありません。

筆者の整理：欠陥は部品（Brotli）にありますが、直すのは、その部品を同梱するソフトウェアのそれぞれです。更新したつもりでも、イメージや実行ファイルは、作り直すまで直りません。HTTP の応答の展開のような、普段は意識しない処理が、入口になりました。Node.js の発表は、この欠陥の報告者を、AI を使った脆弱性の調査道具（OpenAI Codex Security）としています。AI が脆弱性を見つける時代の守り方は、別のまとめ（AI が脆弱性を見つける時代の守り方）でも扱っています。また、同じ Node.js のリリースには、DNS や TLS の検証の欠陥など、ほかの修正も入っています。ひとつの欠陥だけを見て、更新を見送らないことも大切です。
