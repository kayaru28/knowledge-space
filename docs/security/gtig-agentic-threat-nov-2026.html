AI を使った攻撃が「人の手を離れ」始めた：Google の脅威インテリジェンスが初めて確認した、脆弱性の発見から悪用までを自動化した枠組みと、5つの傾向

Google Threat Intelligence Group（GTIG）が2026年11月17日に公表した、AI を悪用する攻撃者の四半期の報告をもとに、脆弱性の発見と悪用の完全な自動化、マルチエージェントの攻撃の枠組み、LLMJacking、情報工作の5つの傾向を、Google 自身の調査と評価として整理する。

初回公開 2026-11-20 ／ 更新日 2026-11-20

ひとことで言うと

Google Threat Intelligence Group（GTIG）は、2026年11月17日の報告で、この四半期に、攻撃者が、大規模言語モデル（LLM）の枠組みを使って、脆弱性の発見と悪用を、人が介在しないまま完全に自動化したのを、初めて確認したと書きました。

報告は、傾向を5つ挙げています。(1) 自律的なマルチエージェントの攻撃の枠組み、(2) 脆弱性の調査と悪用の自動化、(3) LLM の認証情報の窃取と転売（LLMJacking）、(4) 情報工作への LLM の組み込み、(5) 標的の調査と、コーディング支援ツールを使った供給網への攻撃。「完全な自動化」という表現は、GTIG の評価です。

完全な自動化の例：exploit_agent

  • GTIG は、外部から見える状態になっていた検証用のサーバーで、マルチエージェントの脆弱性の調査と悪用の枠組み（「exploit_agent」と名付けた）を見つけた。複数の最先端のモデルと、手元で動くモデルに接続していた。
  • 動き：人気の Web アプリケーションのソフトウェアについて、パッチが発表される前と後のコードを、継続的に比べる。差分を解析して、脆弱性の可能性を見つけ、悪用のコードを書き、人の介在なしに自動で実行する。
  • あわせて、被害者から盗んだデータと、侵害後の活動（内部の偵察、総当たりの攻撃、ウェブシェルの設置、他の攻撃者のウェブシェルの削除）に使うスクリプトが見つかった。サーバーの被害者の記録から、運営者は、フランスのメディアなどに関連する Web サイトを標的にしていたとみられる、と書く。
  • 環境設定のファイルには、ロシア語のコメントで、自動悪用のために、複数の LLM の API キーを設定する指示があった。
  • 解析の例として、WordPress のプラグイン「Spectra（Ultimate Addons for Gutenberg）」のバージョン 2.19.25 の、アクセス制御の実装を点検している画面が載っている。

GTIG は、これらの枠組みが、速度の代わりに隠密性を手放していると書いています。制限のない自律的な実行は、調査の手がかりになる通信を生み、識別できる印を使い、コードの痕跡を残すため、検知の可能性は上がるが、目的の達成には十分な力がある、という評価です。

脆弱性の数字と、修正から悪用までの短縮

  • GTIG は、2026年9月に、脆弱性の統計を調べた。2026年1月から8月で、公開された脆弱性とその悪用は、ほぼ2倍になった。一方、ゼロデイの悪用は、2025年の月平均が8件、2026年が11件で、わずかな増加にとどまり、8月に22件に急増した。
  • n-day（修正済みの脆弱性）は、ゼロデイを探すより、調べる材料が限られる（ソースコードの版の比較、リリースノート、研究、概念実証のコード）。そのため、攻撃者にとって、LLM で素早く悪用の道具にしやすい、という見方を書く。
  • 例（オープンソースの調査）：2026年8月下旬、PaperCut の印刷管理サーバーの2つの脆弱性（CVE-2026-81578 の認証回避、CVE-2026-82078 の安全でない動的クラスの読み込み）が、ゼロデイとして、連鎖させて使われ、認証なしでリモートからコードを実行できた。
  • 例：PHP の脆弱性（CVE-2026-109618、CVE-2026-109619）は、LLM を使った解析で見つかった。公式のパッチ（2026年10月21日）の前に、概念実証の動画と、修正の初期のコードが公開され、研究者も攻撃者も、コードを比べて欠陥を理解し、悪用の作成を試みられた。

LLMJacking と、情報工作

  • LLMJacking：2026年を通じて、Mandiant は、利益目的の攻撃者がクラウドの環境を侵害して、標的の組織のクラウドの計算資源や LLM の利用枠を使い切った事案に、複数対応した。数時間で利用量と請求が急増し、1日に10万ドルを超える不正な請求が出た例もある。最も深刻な例では、対処までの累計が100万ドルに達した。
  • 手口の共通点：金融、小売、運輸、技術の組織で見られた。権限の昇格では、LiteLLM のサンドボックスからの脱出の脆弱性（CVE-2026-40217）で、限定的な推論キー（Virtual Keys）を、管理者の認証情報に引き上げた例がある。権限のあるサービスアカウントで、マルウェアなしに、居座りを成立させていた。
  • 情報工作：GTIG は、情報工作の攻撃者が、LLM の試しから、日常の運用への完全な組み込みに進んだと、高い確度で評価している。商用の影響工作の業者が、Gemini の API を含む複数の提供元を組み合わせて、100,000を超えるアカウントを管理する一括型の基盤を作っていた例を挙げる。

Google が書く対策

  • Google Security Operations で、ARTEX の使用を検知する、ふるまいと量の検知ルールを展開した。
  • Mandiant Consulting が、LLM を使った攻撃の道具の、速さと規模の優位に対抗するための、強化の手引きと、設計上の防御の枠組みを公開した。
  • モデルの安全策、悪意のあるプロジェクトとアカウントの先回りの停止、Big Sleep（脆弱性を探す AI のエージェント）などで、防御を続ける、と書く。

読むときの注意（筆者の整理）

  • 報告は、Google 自身の観測と評価です。「初めて」「完全な自動化」といった表現も、GTIG の評価です。独立した確認は、読んでいません。
  • GTIG は、これらの枠組みが使うのは、侵害された認証情報や、未修正のシステムといった、従来と同じ入口だと書いています。変わったのは、速度と規模です。
  • このまとめは、報告にある技術の再現手順は載せません。

用語メモ

LLMJacking
盗んだ認証情報で、他人のクラウドの LLM の利用枠や計算資源を勝手に使うこと。
n-day
すでに修正版が出ている脆弱性。修正前の期間に、悪用される。
ゼロデイ
修正版が出る前から悪用されている、または悪用されうる脆弱性。
差分解析（differential analysis）
修正の前と後のコードを比べて、何が直されたかを調べること。
OODA ループ
観察、状況判断、決定、行動を繰り返す、意思決定の型。
MCP（モデル コンテキスト プロトコル）
LLM が、外部のツールやデータに接続するための共通の規格。
