Tor の出口の約1割が乗っ取られた：SSH の盗み見と、運営者のサーバーから始まった侵入

2026年10月2日から、Tor の出口の中継点333台が SSH の接続を盗み見するように書き換えられた。接続が回される仕組み、8月の侵入から10月5日の停止までの流れ、出口の数の変化、分かっている侵入の経路、利用者と運営者がすることを、Tor Project の注意喚起と発見者・運営者の報告から図で整理する。

初回公開 2026-10-23 ／ 更新日 2026-10-23

ひとことで言うと

匿名で通信するための Tor のネットワークで、2026年10月2日から、出口の中継点（Tor の通信がふつうのインターネットに出ていく所）の一部が、SSH の接続を盗み見するように書き換えられました。発見者が全部の出口を調べたところ、約3,000台のうち333台、およそ1割が乗っ取られていました。

Tor Project は10月4日に、該当の中継点を出口として使わせないようにし、10月5日までにすべてが止まりました。暗号そのものは破られていません。パスワードを盗まれたのは、SSH の「接続先の鍵が変わった」という警告を無視してログインした人です。

乗っ取られた出口で何が起きたか

Tor は、通信を3つの中継点で包んで送ります。最後の出口から先は、ふつうのインターネットの通信です。乗っ取られた出口を通っても、暗号化された Web の通信はそのまま流れました。回されたのは、SSH（サーバーに遠隔でログインする仕組み、ポート22）の接続だけです。

メールについても、乗っ取られた中継点は、送受信に使うポートのうち25、465、587、993、995を閉じていました（被害を受けた運営者が、書き換えられた設定で確認）。発見者は、暗号化されていないメールだけを通して集める狙いとみています。ただし、メールが実際に盗まれたかは確認されていません。

対応の流れ

侵入は、動き始める1か月以上前から始まっていました。発見から止まるまでは、週末をはさんだ4日間です。

出口の数は戻っていない

Tor Project の統計では、出口のフラグを持つ中継点は、10月4日の3,013台から、10月5日には2,715台へ、1日で298台減りました。その後も2,700台前後で、9月の初めの水準には戻っていません。

どうやって入られたか

侵入の経路が分かっているのは、被害を報告した1組の運営者の場合だけです。運営者自身が、「根本の原因は私たちにあった」として、次の点を挙げています。

  • 1つのパスワードを、SSH のログイン、管理者の権限への切り替え（sudo）、バックアップの暗号の3つに使い回し、両方のサーバーに暗号化せずに置いていた。
  • インターネットに面した管理用のサーバーで、SSH のパスワードでのログインを許していた。攻撃者は、最初に接続したときすでにパスワードを知っていた。
  • 管理用のサーバーが、ほかのサーバーへの入口を兼ねていた。攻撃者はそこから、出口のサーバーに入った。

この運営者の中継点は、10月6日の時点で、57の IP アドレスの168台が止まっていました。入れられた Ebury は、正規のパッケージを書き換えずに別のファイルとして置かれていたため、パッケージの検証では見つからなかったとしています。

ほかの運営者のサーバーにどう入ったかは、分かっていません。ホスティング会社が侵入されたという説もありますが、発見者は推測の段階としています。Ebury を長く調べている研究者は、2009〜2023年に Ebury が入ったサーバーは40万台にのぼり、ほかにも感染した中継点がある可能性が高いと書いています。

利用者と運営者がすること

SSH を使う人

  • 「接続先の鍵が変わった」という警告を無視しない。
  • パスワードでのログインをやめ、鍵でログインする（発見者のすすめ）。
  • 10月2日〜5日に Tor 経由で SSH にパスワードでログインし、警告を無視した場合は、そのパスワードを替え、サーバーを点検する（筆者の整理）。

中継点の運営者（Tor Project の注意喚起）

  • 設定していない Exit のフラグや出口の方針がないか、Tor Metrics の Relay Search で確かめる。
  • torrc に、ExitRelay、ExitPolicy、MyFamily などの変更がないか確かめる。
  • ポート22を転送する規則、知らない通信、tor のプログラムとパッケージの一致、新しいユーザー・鍵・定期実行の設定を確かめる。

侵入が疑われたら（Tor Project の注意喚起）

  • 中継点を止め、ディスクと記録を残す。
  • 掃除ではなく、入れ直す。
  • 中継点の鍵は盗まれたものとみなして作り直し、置いてあった認証情報をすべて替える。

見方

Tor の出口から先は、ふつうのインターネットの通信です。出口が悪意を持てば、暗号化されていない通信は読めますし、暗号化されていても、利用者が鍵の確認を飛ばせば盗み見できます。今回の特徴は、悪意のある人が中継点を立てたのではなく、善意の運営者のサーバーが乗っ取られた点です。守りを最後に支えたのは、SSH の鍵の確認でした。中継点は、多くの人の通信が通る、狙われやすいサーバーとして守る必要があります。

用語メモ

Tor
通信を3つの中継点で何重にも包んで送り、送り手を分かりにくくする仕組み。中継点は世界中の有志が運営している。
出口の中継点（出口ノード）
Tor の通信が、ふつうのインターネットに出ていく所。出口から先の通信は、Tor の暗号で包まれていない。
SSH
サーバーに遠隔でログインして操作する仕組み。通信は暗号化され、接続先の鍵で相手が本物かを確かめる。
中間者攻撃
通信の間に割り込み、両方の相手になりすまして中身を見る攻撃。
Ebury
Linux のサーバーに入れられる、SSH の裏口と認証情報を盗むマルウェア。2009年ごろから確認されている。
BadExit
Tor のディレクトリ機関が、問題のある中継点に付ける印。付いた中継点は出口として使われない。
torrc
Tor の中継点の設定ファイル。出口にするか、どの通信を通すか（出口の方針）を書く。
