預ける基盤で相次いだ事案：Railway の環境変数、Dreamhost のパスワード初期化、Cloudflare Workers AI の他の顧客のデータの混入

2026年10月下旬に公表された、Railway（環境変数への不正アクセスの可能性）、Dreamhost（メールと FTP/SFTP のパスワードの予防的な初期化）、Cloudflare（Workers AI で他の顧客の要求のデータが応答に混ざった問題）を、各社の公式の発表から整理し、原因と利用者への案内の違いを比べる。

初回公開 2026-10-27 ／ 更新日 2026-10-27

ひとことで言うと

2026年10月下旬、開発者やサイト運営者が預けるサービスを提供するプラットフォーム事業者で、利用者の情報や認証情報に関わる事案が公表されました。Railway は、顧客の環境変数に第三者がアクセスした可能性を公表し（10月21日）、Dreamhost は、メールと FTP/SFTP の利用者のパスワードを予防として初期化しました（10月23日から）。Cloudflare は、AI モデルの基盤で、他の顧客の要求のデータが応答に混ざった問題の報告を公表しました（10月26日）。

3件は、原因も性質も違います。Railway は不正アクセス、Cloudflare はソフトウェアの不具合と設定のミス、Dreamhost は原因が公表されていません。この記事は、各社の公式の発表を並べて、何が分かっていて、何が分かっていないかを整理します。

Railway（アプリの展開基盤）10月21日顧客の環境変数を保管するシステムで異常な活動を検知。暗号化された環境変数に第三者がアクセスした可能性があり、一部は復号された内容を取得された可能性がある（環境変数には API キーやデータベース、レジストリの認証情報が含まれうる）不正アクセス。同社は、AI の推論事業者の侵害を狙う、プラットフォーム企業への一連の攻撃の一部と考えている保管している環境変数（API キーを含む）と、非公開のレジストリの認証情報を、すぐに更新する。該当するサービスのログに異常がないかを調べる。展開は停止中
Dreamhost（ホスティング）10月23日から。10月26日にも更新メールと FTP/SFTP の一部の利用者のパスワードを、予防として初期化。パネルのファイルマネージャー（files.dreamhost.com）を停止、一部のウェブメールの利用者がサインアウトされた公表されていない（「いくつかのシステムに影響する問題」と書かれている）影響を受けるアカウントの所有者に、手順をメールで案内。メールを待たずに、パネルで新しいパスワードを設定してもよい。同社はパスワードをメールで尋ねない
Cloudflare（Workers AI）10月26日（9月8日に報告を受け、9月9日に対処）GLM-5.3 のモデルで、非常に長いプロンプトに対し、直前の他の顧客の要求のデータを含む応答が返った。8月27日から9月9日まで、155件AI モデルを動かす推論エンジン（SGLang）の設定のミスと、エンジンの不具合の2つが重なった個別の連絡については書かれていない。他のモデルは影響を受けていない。故意の悪用の証拠は見つかっていない

Railway：環境変数への不正アクセスの可能性

  • 10月21日の朝に、顧客の環境変数を保管するシステムで異常な活動を検知した。調査の結果、暗号化された環境変数に第三者がアクセスした可能性があり、一部は復号された内容を取得された可能性がある、としている。
  • 影響の範囲：初期の分析では、一部の利用者に限られる可能性があるとしつつ、完了するまでの予防として、すべての利用者に、環境変数（API キーを含む）と、非公開のレジストリの認証情報をすぐに更新し、ログで不審な活動がないかを調べるよう強く勧めている。影響を受けたアカウントは、確認でき次第、個別にメールで連絡する。
  • 上流への通知：同社は、一連の攻撃の目的が AI の推論事業者の侵害にあると考えていて、上流の事業者に、すべてのキーを先回りして無効にするよう連絡した、と書いている。
  • 展開の停止：調査中は、すべての展開を停止した。10月23日の同社の別のブログ記事は、10月21日に展開を止めている間に push したコミットは展開されていないとして、最新のコミットを再展開し、GitHub を再接続し、CLI と CI の認証情報を作り直すよう案内している。
  • 公開されていないこと：影響を受けた利用者の数、侵入の経路、取得された情報の具体的な範囲は、発表に書かれていない。

Dreamhost：予防としてのパスワードの初期化

  • 10月23日 14:20（太平洋時間）に、ファイルマネージャーの接続の問題として調査を始めた。17:20に、複数のサービスに影響する事案として、ファイルマネージャーが停止し、一部のウェブメールの利用者がサインアウトされていると更新した。
  • 予防として、一部のメール利用者のパスワードを初期化した。のちに、メールと FTP/SFTP の一部の利用者の初期化が完了したと更新した。10月25日の夜（太平洋時間）に、影響を受けたすべてのアカウントの所有者に、手順をメールで送り終えた。
  • 10月26日：ファイルマネージャーの修正を公開し、復旧した（監視中）。メールと FTP/SFTP の一部の利用者には、パスワードの再設定が引き続き必要。
  • 利用者向けの注意：同社はパスワードをメールで尋ねない。パスワードの変更は、パネル（panel.dreamhost.com）から直接行う。心当たりのない再設定のメールは無視する。
  • 公開されていないこと：事案の原因、影響を受けた利用者の数、情報が外部に取得されたかどうかは、ステータスページには書かれていない。

Cloudflare：他の顧客の要求のデータが応答に混ざった

  • 経緯：9月8日に、セキュリティ研究者から HackerOne の窓口を通じて報告を受けた。翌9日に再現を確認し、事案を宣言した。宣言から40分以内にモデルを停止し、同日に設定の修正とエンジンのパッチを適用して、19:40に復旧した。公開は10月26日で、研究者とエンジンの開発元との共同の公開。
  • 影響：2026年8月27日に GLM-5.3 を Workers AI で開始してから9月9日までのあいだに、少数の顧客が、同じモデルへの直前の他の顧客の要求のデータを含む応答を受け取った。合計155件で、すべて681,280トークンを超えるプロンプトへの応答。同社は、研究者と自社のテストを除くと、通常の長い文脈の使い方と一致しており、故意の悪用の証拠は見つからなかった、としている。他のモデルは影響を受けていない。
  • 原因1（設定のミス）：モデルの文脈の長さは1,048,576トークンだが、事前計算（prefill）用の GPU の KV キャッシュの領域は681,280トークンぶんしかなかった。同社は開始前にこの不一致を認識していたが、長い文脈の試験が成功の応答を返したので、問題ないと考えた。試験は、応答の状態コードと性能だけを見て、出力の中身や一貫性は検証していなかった。
  • 原因2（エンジンの不具合）：領域に入らない長さの要求は、エンジンが拒否として扱い、1トークンの代わりの文面に差し替える。1台で動かす構成ではエラーが返るが、事前計算と生成を別のノードに分ける構成では、拒否された要求が通常の要求と同じく進み、生成側が、以前の要求が残した領域（他の顧客のプロンプトや途中の生成）を読んで応答を作り、HTTP 200で返していた。
  • 対処：KV キャッシュの領域を文脈の長さの約2倍（約204万トークン）にして、拒否の経路に入らないようにした。さらに、エンジンのパッチで、拒否された要求を早い段階で、元のエラーとともに終了させる。上流の SGLang も、v0.5.20〜v0.5.22 で修正し、同社はすべての運用者に v0.5.22 以降への更新を強く勧めている。
  • 今後の取り組み：KV キャッシュの領域の解放と共有の不具合は、同社が数か月前から取り組んでいる種類の問題として、ほかの修正も上流に提案している。新しい展開では、領域の大きさと文脈の長さの照合などを、チェック項目に加えた。

読むときの注意

  • 3件に共通する原因はない：Railway の侵害について、同社は一連の攻撃との関連を述べているが、Dreamhost と Cloudflare の事案との関連は、各社の発表に書かれていない。この記事も、関連を主張しない。
  • 各社の自己申告：影響の範囲や原因は、各社の説明。Railway の「一連の攻撃」という見方も、同社の推測で、攻撃者や手口の裏づけは示されていない。
  • 進行中の事案：Railway と Dreamhost は、公表の時点で調査や復旧が続いている。影響の範囲や原因は、続報で変わる可能性がある。
  • Cloudflare の公表は、対処の約7週間後：問題の発生から対処までは短い（40分以内に停止）が、公開は10月26日で、上流のエンジンの修正との共同の公開にそろえている。

見方（筆者の整理）

  • 預ける側の利用者にとっての共通点は、事業者の側の事案で、自分の側からは防げず、通知を待って更新や再設定を行うしかないことだ。環境変数の更新、パスワードの再設定は、手順が決まっている。更新が必要なものを、普段から一覧で把握しておくと速い。
  • Cloudflare の事案は、AI の推論基盤特有の問題の例になっている。KV キャッシュの領域は、速さのために、使い回しのあいだにゼロで消されない。そのため、所有の追跡を誤ると、他の利用者の内容が見える。同社は、領域の大きさと文脈の長さの照合のような、基本的な検査の欠けも認めている。
  • 原因が公表されないことも多い。Dreamhost の事案のように、原因が書かれていない間は、利用者はパスワードの再設定という最低限の対応にとどまる。

用語メモ

環境変数
アプリが実行時に読む設定値。API キーやデータベースの接続情報が入ることが多い。
KV キャッシュ
AI モデルが文章を生成するとき、入力の途中結果を GPU のメモリに保存しておく領域。再計算を省いて速くするために使う。
推論エンジン（SGLang）
AI モデルを動かして応答を作る、オープンソースの基盤ソフトウェア。
テナントの分離
複数の顧客が同じ基盤を使うとき、顧客ごとのデータが混ざらないようにする仕組み。
FTP/SFTP
ファイルをサーバーに転送する方式。ホスティングでサイトのファイルを置くのに使う。
協調した公開
脆弱性などを、報告者、事業者、開発元が足並みをそろえて公表すること。
