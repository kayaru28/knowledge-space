楽天証券の情報漏えい：テスト環境から、個人情報約441万件と、IDのみの約1,198万口座（11月24日の第2報）

楽天証券への不正アクセスによる情報漏えいを、公式のお知らせから整理する。11月24日の第2報で示された、個人情報の漏えい約441万件と、IDのみの約1,198万口座、追加で確認された項目、確認されていないこと。11月17日の第1報の内容と利用者への案内も載せる。

初回公開 2026-11-19 ／ 更新日 2026-11-28

ひとことで言うと

11月24日の第2報で、楽天証券は漏えいがわかったとして件数を示しました。部店・お客様コードとログインIDに加え、氏名、カナ氏名、生年月日、住所、電話番号などの個人情報の漏えいは約441万件。漏えいが部店・お客様コードとログインIDに限られるのは約1,198万口座です。取引に必要なパスワードや暗証番号などの漏えいと、本件に起因すると考えられる不正アクセス・不正取引は、確認していません。次の段落からは、第1報（11月17日）の時点の内容です。

楽天証券は、2026年11月16日（月）に、一部のシステムへの第三者による不正アクセスの可能性を検知し、調べた結果、11月11日（水）に、テスト環境のシステム内で管理していた一部の情報が外部に漏えいしたおそれがあることを確認した、と公表した。

対象は、楽天証券に登録していた顧客（退会した顧客を含む）。部店・お客様コードとログインIDは最大約1,125万口座分、そのうち、氏名・住所・生年月日・電話番号・メールなどまで含むものが最大約447万口座分。ログインに必要なパスワードや暗証番号など、取引に必要な各種の情報の漏えいは確認していない。本件に起因すると考えられる不正アクセスや不正取引も、現時点では確認していない。

11月24日の第2報で示されたこと

  • 約441万件の内訳：約322万口座は口座を持つ顧客の情報、約119万件は口座を開設していない人の情報。重複を含む可能性がある（申し込みを途中でやめて、改めて申し込んだ場合など）。
  • 第1報の項目に加わった7項目：性別、国籍、FAX番号、入金先口座の情報（楽天証券の口座の情報）、口座の開設・受付・解約の状況、口座開設時のアンケート、口座の登録状況。
  • 資産などの情報：商品別の資産の情報は約168万件、顧客が申告した年収の情報は約1.4万件、申告した資産の情報は約271万件。年収と資産は、選んだ番号だけで、詳しい金額は含まない。商品別の資産の情報は、各商品と預かり資産の残高で、保有する銘柄や取引の情報は含まない。
  • 確認していないもの：ログインに必要なパスワード、暗証番号を含む取引に必要な各種情報の漏えいと、本件に起因すると考えられる顧客の口座への不正アクセス・不正取引。

漏えいのおそれがある情報（第1報の時点）

  • 最大約447万口座：楽天証券の部店・お客様コード、ログインID、氏名、カナ氏名、生年月日、住所、電話番号、メールアドレス、勤務先、出金先口座（金融機関・口座番号・名義人）、年収・金融資産（お客様ご申告情報）、商品別資産情報、最終ログイン日。
  • 最大約1,125万口座：楽天証券の部店・お客様コード、ログインID。
  • ログインIDは、楽天IDとは異なる、と注記されている。
  • 漏えいを確認していないもの：ログインに必要なパスワード、暗証番号を含む、取引に必要な各種情報。

楽天証券の対応と案内

  • 11月16日に、該当箇所へのアクセスの遮断と修正をした。原因と詳しい経緯は、調査中。
  • 影響が確認された顧客の特定は完了していて、該当の顧客には個別に報告する。新しい事項は、改めて連絡する。
  • 利用者への案内：楽天証券のメールには URL を載せていない。電話で個人情報やログインの情報を尋ねることはない。楽天証券や関係会社を装った不審なメール・SMS・電話・郵送物に注意する。
  • パスキー認証（フィッシングへの耐性が高い）のログインの必須化を進めていて、日々ログインする顧客の9割超が使っている。未設定の人は設定する。取引や出金の一時的な利用停止は、ログイン後のセキュリティ設定で、顧客自身が設定できる。

読むときの注意

  • 読んだのは、2026年11月17日付と11月24日付のお知らせ。以後の更新は未確認。
  • 不正アクセスの原因と侵入の方法は、書かれていない。第2報は、原因の究明を進めているとしている。
  • 第1報の件数は口座の数で、人数ではない。第1報の2つの数字（約447万と約1,125万）の関係は、約447万口座が約1,125万口座の一部とは明記されていない。一部と読むのが自然だが、書かれていない。
  • 同社が10月31日と11月5日に公表した、外部のサービス提供元・委託先の件とは、別の事案として公表されている。つながりがあるかは、読んだ文書に書かれていない。

見方（筆者の整理）

  • 「テスト環境」に、本番の顧客情報（出金先口座や年収・金融資産のような申告情報を含む）が置かれていた点が目を引く。なぜテスト環境にこれらがあったかは、書かれていない。
  • パスワードと暗証番号の漏えいは確認していない、としている。それでも、氏名、住所、電話、メール、出金先口座の情報がそろうと、本人を装う連絡に使われやすい、という一般的な懸念がある（筆者の整理）。
  • 楽天証券は、パスキー認証を案内し、一時的な利用停止の設定を勧めている。利用者が自分でできる備えが、お知らせの中心に置かれている。
