国内で相次ぐ不正アクセスによる情報漏えい：何が起きていて、組織は何を点検すべきか

2026年9月ごろから国内で続く漏えいについて、各組織の公式発表と、JPCERT/CC・IPA の注意喚起をもとに、具体的な事例（51組織）、外部サービスからの波及、塞いだ後に残った裏口、確認されている攻撃の入口、組織がすぐ行う点検を図で整理する。

初回公開 2026-10-19 ／ 更新日 2026-10-31

ひとことで言うと

2026年9月ごろから、国内の組織で、不正アクセスによる個人情報の漏えいの公表が相次いでいます。JPCERT/CC と IPA は、10月上旬に続けて注意喚起を出しました。

特徴は、原因が1つの脆弱性に絞られていないことです。外部に公開しているアプリやAPI、利用中の外部サービスのアカウントなど、入口が複数にまたがっています。

10月16日から19日にかけても、百貨店、通信事業者、Web制作サービス、家電量販店、スポーツ団体などで、不正アクセスの公表が続きました（10月20日追記）。

10月19日から20日にかけては、メール配信サービス、防災情報などの一斉配信サービス、通信事業者の会員サイト、システム開発の委託先、医療機関向けのサービス、電子書籍サイトなどで公表が続きました（10月21日追記）。

10月20日から22日にかけては、ゲーム会社の会員 ID（約1,177万件）、中古車情報サイト（最大約371万件）、電子書籍ストア（最大約420万件）、放送局、大学などでも公表が続きました。JPCERT/CC は、攻撃者がアプリを解析して API を見つけ、AI も使って攻撃していたことを確認しています（10月23日追記）。

10月23日の公表分では、これまで「調査中」だった件数が確定し、数字が大きく動いたものがありました。佐川急便は、流出の可能性がある個人情報を最大約5,323万件（重複を含む）と公表し、タイムズカーは、本人確認書類の画像の漏えいを約160万件から約146万件に訂正しました。生成AIに個人情報をアップロードして起きた漏えいも公表されています（10月25日追記）。

10月21日から26日にかけては、オンラインストア、旅行予約サイト、大学（NEC への委託経由）、物流子会社、ホテルのメール配信の外部サービス、情報セキュリティ製品の会社での公表が続き、カプコンと Joshin の続報で影響範囲が分かってきました。タイムズカーの運営会社は、見舞金などの費用を特別損失として見込むと公表しました（10月27日追記）。

10月26日と27日には、ユミルリンクが第二報で、漏えいした延べ件数を約900万件から51,628,280件に改めました。この件の波及先として、JR 東海・西日本・九州の「エクスプレス予約」と「スマートEX」が公表し、So-net は、会員情報などの漏えいを公表しました（10月29日追記）。

10月24日から30日にかけて、GMO インターネットの「お名前.com デスクトップクラウド」への攻撃（金銭の要求と、利用者の情報の公開）、日本航空・日本トランスオーシャン航空の予約システム（委託先のシステムへの不正アクセス）、ヤクルト本社の公式サイト（約4万件）の公表が続きました（10月31日追記）。

4類型

JPCERT/CC が整理した攻撃の入口

3点検

IPA が経営者に求める点検（公開アプリ・外部サービス・保有データ）

何が起きているのか

  • 金融機関や通信事業者など、幅広い業種で公表が続いています（IPA）。
  • 大量の個人情報を扱うオンラインサービスやアカウントサービスが、侵入を受けています（IPA）。
  • 利用者向けのアプリだけでなく、BIツールや従業員向けの管理システムのように、不特定多数の利用を想定していないシステムでも、保存している情報が漏えいした例があります（JPCERT/CC）。
  • 特定の製品やサービスの脆弱性を狙った攻撃とは、現時点では断定されていません（IPA、JPCERT/CC）。
  • 技術的な情報の共有が十分ではなく、把握できていることは限られていて断片的です。新しい情報が分かれば、注意喚起は更新されます（JPCERT/CC）。

企業の側から見た数字（10月21日追記）：帝国データバンクの企業アンケート（10月9〜14日、1,328社が回答）では、情報漏えい（可能性のある事案を含む）が「発生したことがある」企業は16.2%、大企業では30.2%でした。「分からない」と答えた企業も14.8%あり、発生したかどうかを把握できていない企業もあります。

続報から見えること

ここは、各組織の発表を並べて読んだ上での整理です。各組織がそう述べているわけではありません。

  • 外部サービスから波及します。Studio の件では、侵入を受けたのはWeb制作サービス1社ですが、それを使ってサイトを作った組織と、そのフォームに入力した人の情報にまで影響が広がりました。IPA が点検を求める「自組織が使っている外部サービス」の重要さを示す例です。
  • 暗号化だけでは守れない場合があります。Studio は、暗号化して保存していた情報も、復号に必要な鍵が同じ不正アクセスで読み出されたと説明しています。鍵をデータと同じ場所に置いていると、暗号化の効果は薄れます。
  • 共通のIDは、被害が広がります。阪急阪神百貨店では、予約サイト経由の侵入で、複数のサービスに共通の会員ID（H2O ID）のほぼ全会員分が漏えいしました。
  • 盗んだパスワードを使い回す攻撃もあります。スクウェア・エニックスは、他社で流出した組み合わせを使った不正ログインを確認しています。パスワードの使い回しをやめることは、利用者側の対策にもなります。

さらに見えること（10月21日追記）

ここは、各組織の発表を並べて読んだ上での整理です。各組織がそう述べているわけではありません。

  • 委託先や配信サービスから広がります。NEC は委託先、アルカディアとユミルリンクは多くの組織が使う配信サービスです。Studio と同じく、自組織が直接侵入されなくても、使っている外部の事業者を通じて情報が漏れます。
  • 秘密の鍵や認証情報が突破口になります。アルカディアは、設定ファイルにあったサービス間ログイン用の秘密鍵を取られました。ユミルリンクは、担当者の認証情報を取られました。Studio の「復号の鍵」と同じく、鍵を、侵入されうる場所に置かないことが重要です。
  • 塞いでも、裏口が残ることがあります。アルカディアは、侵入経路を塞いだ後に、仕込まれていた裏口から不正なメールを送られました。経路を塞ぐだけでなく、侵入中に何を置かれたかを調べる必要があります。
  • 作り直して再開する例も出ました。メドレーは、既存のシステムを再稼働させず、別の環境に作り直して再開します。
  • リスト型攻撃は、自社から漏れていなくても起きます。日本郵政は、自社システムからの漏えいは確認されていないものの、外部で漏えいしたIDとパスワードで、249アカウントにログインされました。

アプリを解析して API を狙う（JPCERT/CC の調査）

JPCERT/CC は10月21日、攻撃に使われた可能性のあるサーバーの調査結果を公表しました。攻撃者は、Android のアプリの配布ファイルを解析して API を特定し、サーバー側から別の場所へ通信させる脆弱性（SSRF）がないかなどを調べていました。攻撃者が AI を使って、既知の脆弱性の探索や API を通じた攻撃をしていたことも確認したとしています。同じような攻撃元のサーバーは複数あり、日本以外の Web サービスも狙われていました。

JPCERT/CC は、アプリの中のコードはコンパイルされていても、埋め込まれた秘密の鍵や API の認証の処理を取り出せる場合があるとして、次の対策を勧めています。

秘密をアプリに入れない

API の認証に使う秘密の鍵や、有効期間の長い認証情報を、アプリに埋め込みません。

サーバー側で確かめる

アプリの中の署名や難読化だけに頼らず、サーバー側で利用者を認証し、操作の対象や内容に応じて許可します。

正規のアプリ以外も想定する

回数の制限や異常なリクエストの監視で、正規のアプリ以外からのアクセスも想定して API を守ります。

SSRF を防ぐ

外部の URL の内容を取りに行く API では、行き先を制限し、転送された後の行き先も確かめます。

組織がすぐ行う点検

IPA は、経営者に向けて、次の3つの点検を速やかに行うよう求めています。異常なログやアカウントが見つかったときは、速やかにセキュリティインシデントとして扱います。漏えいの可能性があるため、専門のセキュリティベンダーへの調査依頼が強く勧められています。

APIまわりの対策（JPCERT/CC）

回数を制限する

一定時間あたりのリクエスト数を制限します。ログインやパスワードの再設定、SMS送信、検索のように、悪用されやすい機能には、個別の制限を設けます。

入口ごとに制御する

非公開のものも含め、APIの出入口ごとにアクセス制御を行い、許可された利用者と操作だけを受け付けます。

権限と期限を絞る

利用者やトークンには必要最小限の権限だけを与え、有効期限をつけます。不要になったものや漏えいが疑われるものは、すぐ無効にできるようにします。

公開しない

業務で使わない管理機能などが、インターネットに公開されていないかを確認します。

利用者として気をつけること

ここは注意喚起の内容ではなく、一般的な心がけです。各社の発表にも、同じ趣旨の呼びかけがあります。

連絡は公式から確認する

漏えいの連絡を名乗るメールやSMSのリンクは開かず、公式サイトや公式アプリから状況を確認します。

パスワードを使い回さない

ソースネクストは、全会員のパスワードを無効にした上で、同じメールアドレスとパスワードの組み合わせを他のサービスでも使っている場合は、そちらも変更するよう求めています。スクウェア・エニックスと日本郵政は、他社で流出した組み合わせを使った不正ログインを確認しています。

多要素認証を有効にする

多要素認証が使えるサービスでは、有効にします。
