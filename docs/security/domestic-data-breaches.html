国内で相次ぐ不正アクセスによる情報漏えい：何が起きていて、組織は何を点検すべきか

2026年9月ごろから国内で続く漏えいについて、各社の公式発表と、JPCERT/CC・IPA の注意喚起をもとに、具体的な事例、確認されている攻撃の入口、組織がすぐ行う点検を図で整理する。

初回公開 2026-10-19 ／ 更新日 2026-10-19

ひとことで言うと

2026年9月ごろから、国内の組織で、不正アクセスによる個人情報の漏えいの公表が相次いでいます。JPCERT/CC と IPA は、10月上旬に続けて注意喚起を出しました。

特徴は、原因が1つの脆弱性に絞られていないことです。外部に公開しているアプリやAPI、利用中の外部サービスのアカウントなど、入口が複数にまたがっています。

何が起きているのか

  • 金融機関や通信事業者など、幅広い業種で公表が続いています（IPA）。
  • 大量の個人情報を扱うオンラインサービスやアカウントサービスが、侵入を受けています（IPA）。
  • 利用者向けのアプリだけでなく、BIツールや従業員向けの管理システムのように、不特定多数の利用を想定していないシステムでも、保存している情報が漏えいした例があります（JPCERT/CC）。
  • 特定の製品やサービスの脆弱性を狙った攻撃とは、現時点では断定されていません（IPA、JPCERT/CC）。
  • 技術的な情報の共有が十分ではなく、把握できていることは限られていて断片的です。新しい情報が分かれば、注意喚起は更新されます（JPCERT/CC）。

事例から見えること

ここは、各社の発表を並べて読んだ上での整理です。各社や関係機関がそう述べているわけではありません。

  • 入口はさまざまです。ソースネクストはAPIの不正利用、日本経済新聞社はクラウドの認証情報の窃取を挙げています。ヤマト運輸とバーガーキングは、原因を調査中、または記載なしです。APIの不正な操作は、JPCERT/CC が整理した類型Bと重なります。外部サービスのアカウントは、IPA が点検を求めている対象です。
  • クレジットカード情報は、4社とも対象外としています。ヤマト運輸と日本経済新聞社は「含まれない」、ソースネクストは「対象システムに保存していない」、バーガーキングは「保持していない」と説明しています。
  • 発表時点で二次被害を確認していないと述べたのは、ヤマト運輸、バーガーキング、日本経済新聞社です。
  • 規模が大きいです。100万件から2,000万件超まで及びます。
  • 利用者へは、不審なメール、SMS、電話への注意が呼びかけられています。（ヤマト運輸、バーガーキング、ソースネクスト）

確認されている攻撃の入口

JPCERT/CC は、寄せられた情報をもとに、攻撃の入口を4つの類型（A〜D）で整理しています。すべての事案が同じ手口というわけではありません。IPA は、このほかに、外部サービスのアカウントの侵害が起点になっていると見られるとしています（E）。

A〜D は JPCERT/CC、E は IPA の整理
類型何をされるか見直すポイント
A. 既知の脆弱性の探索組織ごとに、さまざまなソフトウェアの既知の脆弱性を探し、悪用を試みる修正プログラムの適用
B. APIの不正な操作公開されているスマホアプリを解析して、APIの接続先やキーを特定する。画面からは操作できない内部APIを直接呼び出して、権限の変更やアカウントの作成を試みる。ほかのシステムで盗まれたAPIキーが使われることもあるAPIのアクセス制御、回数制限、トークンの管理
C. BIツール Metabase の脆弱性SQLインジェクションの脆弱性（CVE-2026-72898）が、API経由で悪用される該当バージョンの更新
D. Webシェルの設置公開Webサーバーから到達できるアプリケーションサーバーに不正なファイルを置かれ、外部からコマンドを実行される公開範囲の見直し、侵入後の横展開への備え
E. 外部サービスのアカウント外部公開しているサービスやアカウントの侵害が起点になっていると見られる多要素認証、アカウントの棚卸し

組織がすぐ行う点検

IPA は、経営者に向けて、次の3つの点検を速やかに行うよう求めています。異常なログやアカウントが見つかったときは、速やかにセキュリティインシデントとして扱います。漏えいの可能性があるため、専門のセキュリティベンダーへの調査依頼が強く勧められています。

APIまわりの対策（JPCERT/CC）

回数を制限する

一定時間あたりのリクエスト数を制限します。ログインやパスワードの再設定、SMS送信、検索のように、悪用されやすい機能には、個別の制限を設けます。

入口ごとに制御する

非公開のものも含め、APIの出入口ごとにアクセス制御を行い、許可された利用者と操作だけを受け付けます。

権限と期限を絞る

利用者やトークンには必要最小限の権限だけを与え、有効期限をつけます。不要になったものや漏えいが疑われるものは、すぐ無効にできるようにします。

公開しない

業務で使わない管理機能などが、インターネットに公開されていないかを確認します。

利用者として気をつけること

ここは注意喚起の内容ではなく、一般的な心がけです。各社の発表にも、同じ趣旨の呼びかけがあります。

連絡は公式から確認する

漏えいの連絡を名乗るメールやSMSのリンクは開かず、公式サイトや公式アプリから状況を確認します。

パスワードを使い回さない

ソースネクストは、全会員のパスワードを無効にした上で、同じメールアドレスとパスワードの組み合わせを他のサービスでも使っている場合は、そちらも変更するよう求めています。

多要素認証を有効にする

多要素認証が使えるサービスでは、有効にします。
