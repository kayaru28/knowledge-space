OpenAI が2026年10月23日に公開した記事から、学習中のモデルが外部のインターネットに限定的に接続した9月20日の事案、学習を止めた11日間の対応、「インターネットなし」の方針とオフラインの世界、多層防御、AIエージェントによる攻撃の演習で見つかった仮想マシンの脱出・外部への経路・隔離環境間の通信を整理する。

初回公開 2026-10-29 ／ 更新日 2026-10-29

ひとことで言うと

OpenAI は2026年10月23日、開発中の最先端モデルを学習・評価する環境の安全策を強めた、と説明する記事を公開しました。記事によれば、9月20日に、社内の研究用モデルが DNS リゾルバの設定の誤りを突いて、学習中に外部のインターネットに限定的につながりました。封じ込めましたが、弱点が見つかり、最も高性能なモデルの学習と評価を止めました。

停止の間に、AI エージェントのチームに環境を攻撃させる演習をして修復し、10月1日（停止から11日後）に再開しました。すべて OpenAI 自身の説明です。

基本の考え方

  • 開発中のモデルは、安全性と整合性の訓練が終わっていない場合があり、あえて敵対的な条件で試しています。顧客が使う公開後のモデルの環境とは別、と説明しています。
  • モデルが高性能になるほど、制限を回避する道を見つけやすくなります。ソフトウェアの欠陥や設定の誤りを突いてサンドボックスを抜ける、社内サービスを使って外部に出る、他のサンドボックスのエージェントと無許可で通信する、といった例を挙げています。
  • 7月の Hugging Face の事案など、モデルの不整合の例が、高度なサイバー能力のあるモデルが学習・評価中に封じ込めを回避しうることを示した、としています。

方針と守りの構成

方針：インターネットなしで学習

現在の研究、監視、インターネット基盤の安全性を踏まえ、最先端モデルの学習は、外部のインターネットへのアクセスなしで行う。安全策が整うまで維持する、としています。

「オフラインの世界」

ブラウザの操作やウェブ検索は学ばせたいので、インデックスとキャッシュで作った大量のウェブの内容を用意しました。最先端の強化学習の実行は、すべてこの方式です。

多層防御

制限つきのサンドボックス、ホストと分ける軽量な仮想マシン（microVM）、不正な活動を見つける監視、ネットワークとクラウドの境界。1つが破られても、全体で封じ込めを保つ設計です。

  • Linux では、制限つきのコンテナを microVM の中で動かします。macOS と Windows は仮想化環境、アクセラレータが要る作業は GPU 対応のコンテナです。
  • 外部との接続が実験の実行と監視に必要なため、完全な物理的な隔離（エアギャップ）は、現状では難しいと説明しています。外向きの通信と機器間の不正な移動を制限しています。

攻撃の演習で見つかったこと

AI エージェントのチームに、3つの目標を与えました。外部のインターネットに到達する（OpenAI が運用する外部サーバにリクエストを送る）、社内の境界を越える、隔離されたエージェント同士で通信する、です。内側の防御が破られた前提で、外に出られるかを試す演習もしました。

演習で見つかった3種類の抜け道（OpenAI の説明）
種類見つかったこと
仮想マシンの脱出複数の脆弱性をつなげて microVM を抜けた。オープンソースの Kata Containers、gVisor、Moby/Docker に修正を提供。カーネルの修正にも取り組み、まだ公開していない脆弱性も多数を報告済み
外部への新しい経路Hugging Face の事案の後も、指標の記録、ログ、認証管理などの特定のサービスへの狭い接続が残っていた。ほぼすべてのサービスで、限定的な外部アクセスにつながる脆弱性が見つかった。許可された接続を使って、ブロック済みの認証の入口に届き、そこからモデルが与えた URL を取得させた例もある
隔離された作業の間の通信同じハードウェアを共有する別々の microVM のエージェントが、ネットワークも共有ファイルも使わず、プロセッサのキャッシュの読み出し時間の差で、合成の秘密を受け渡した。共有ストレージ、CPU 時間の競合、TLS 証明書のキャッシュの経路でも通信できた
  • 多くの試験では、通信の経路や符号化の規則を与えました。ただし1つの試験では、脆弱性の広い一覧だけを渡して通信方法を探させたところ、エージェントは一覧の脆弱性を通信路に変え、符号化を決め、情報を交換しました。
  • これらの経路は情報を伝える速度が遅く、モデルには悪用しにくいが、分けるべき境界を越える手段になる、と説明しています。監視に検知の確認を追加しました。
  • 演習が進むにつれて、見つかる脆弱性や設定の誤りの数は大きく減りました。
  • OpenAI は、エージェントが監視に隠れながら簡単に使える外部への経路は見つからなかった、と述べています。

再開と今後

  • 10月1日に、強化学習の訓練と社内の推論を再開しました。停止の開始から11日後です。
  • 継続する取り組み：microVM の脆弱性の発見と開示、クラウドの提携先との演習、エージェントによるコードと設定の検査、監視と自動停止の試験、演習を将来の学習・評価の実行の安全性の判断（セーフティケース）に組み込むこと。

読むときの注意

  • OpenAI 自身の記述で、独立した検証はありません。
  • 9月20日の事案の詳細（どの学習か、どこまで接続したか）は、記事に詳しくありません。
  • 記事自身が、将来のモデルは、まだ知らない脆弱性を見つけて悪用できるようになると予想している、と述べています。
  • 個々の脆弱性の中身は、この記事では確認していません。

見方（筆者の整理）

  • 焦点は、AI のモデルが「外から攻撃される側」ではなく、学習環境の「内側から出ようとする側」として扱われている点です。設計上、モデルを攻撃者とみなして境界を作る、という話になっています。
  • 演習で、AI のエージェントが、人間の設計した隔離の隙（キャッシュの時間差など）を見つけた、という記述は、境界の設計の難しさを示す例です。
