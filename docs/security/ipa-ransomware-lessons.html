ランサムウェア被害組織の声から出た11の教訓：IPA の教訓集が、経営者と対処の現場に求めること

IPA が2026年9月に公開した「ランサムウェア被害から学ぶ教訓集 〜経営者のためのランサムウェア対策ハンドブック〜」（ver.1.2）の、経営・リスク管理編6項目とインシデント対処編5項目を、IPA の文書をもとに整理する。

初回公開 2026-11-20 ／ 更新日 2026-11-20

ひとことで言うと

IPA（情報処理推進機構）は2026年9月8日、国内のランサムウェアの被害組織へのヒアリングから抽出した教訓を、「ランサムウェア被害から学ぶ教訓集」として公開しました（最新は2026年10月16日更新の ver.1.2）。教訓は11項目で、経営・リスク管理編が6項目、インシデント対処編が5項目です。

サブタイトルは「経営者のためのランサムウェア対策ハンドブック」です。IPA は、この脅威に立ち向かうには、経営者の明確な関与が不可欠だと確信したため、と書いています。

ランサムウェア事案の特性（教訓集が書く）

  • 時間の猶予が少ない：データが暗号化されて被害に気づいた時点で、すでにインシデントのフェーズの最終段階にあり、侵害の調査、復旧か再構築かの判断、業務の継続、取引先と公表の対応を、短期間にこなす必要がある。
  • 二重脅迫がある：暗号化の前にデータを盗み、身代金を払わなければ暴露する、と後追いで脅すことがある。この場合、発覚の直後から、技術的な対処と、事業継続の対応が重なる。
  • 情報システム部門に負荷が集中する：経営者への報告、事業継続、取引先対応まで、IT 部門に集まりやすい。
  • 平時の備えの差が、成否を分ける：暗号化・漏えいしたデータを特定するための台帳、有事の指揮命令と役割分担、想定外への対応体制などの違いが、一般的な IT インシデント以上に効く。

経営・リスク管理編：6つの教訓

IPA の教訓集（経営者やリスク管理部門が重視すべき教訓）
番号教訓要点（教訓集の記述）
1経営者による迅速な経営判断と明確な関与対応に時間の猶予がない。発覚直後から、業務の中断、脅迫、メディアへの対応で、判断を迫られる。経営者は、起こりうるリスクを事前に認識し、判断の基準と意思決定の手順を、あらかじめ整えておく
2インシデント対応体制の整備IT 部門に負荷が集中する。公表、法務、取引先、外部の組織との連携など、多方面の対応が要る。情報システム、総務、広報、法務、営業を含めて、全社で役割分担を決めておく
3事業継続計画（BCP）への反映システムの停止は、業務の停止に直結しうる。停止・復旧の判断には、事業部門の関与が必須。IT 部門と事業部門の協力のもと、サイバー攻撃に対応した BCP の策定を、指示しておく
4個人情報を含むデータの現状把握流出・暗号化されたデータの中身は、フォレンジック調査をしても、後から特定するのが難しいことが多い。個人情報を含むデータの台帳を、事前に整備するよう指示する
5経営者主導の意思統一組織内の認識のずれは、混乱を招き、対応を妨げる。情報発信や権限委譲などを工夫して、意思統一と、速い対応を実現する
6窃取されたデータの暴露への備え身代金を払っても、データの回復や、暴露の中止は保証されない。この前提で、ダークウェブ上での暴露のリスクに備えつつ、データとシステムの復旧を図る

インシデント対処編：5つの教訓

IPA の教訓集（インシデント対処に当たる部門が重視すべき教訓）
番号教訓要点（教訓集の記述）
1バックアップとログの整合性確保汚染された可能性のあるバックアップは、復旧に使えない。少なくとも、侵入の開始時期より前の時点のバックアップは安全なので、侵入の開始時期を特定することが重要。必要なログを保存し、安全な復元の時点を判断できるようにしておく
2基本的な対策の徹底被害の多くは、基本的な対策ができていないことに起因する。基本的な対策を徹底して続ける。境界の防御に隙を作らず、内部のネットワークが安全ではない前提の対策も維持する
3EDR の導入と定期のログ監査従来型のウイルス対策ソフトだけでは、攻撃者の活動を十分に検知できない場合がある。EDR などを導入し、アラートに素早く対応できる監視体制を整え、定期的にログを確認・分析する
4「漏えいなし」の証明は困難顧客や取引先に、「情報漏えいがなかったこと」を証明するのは、極めて難しい。フォレンジック調査などで分かった事実と、経過の観察の状況を、必要な範囲で丁寧に報告する
5セキュリティベンダーとの関係構築ベンダーの役割は大きい。ただし、組織の体制やインシデントの状況で、求める役割は違い、ベンダーごとに対応できる範囲も違う。平時から、必要な役割と範囲を把握し、適切なベンダーを選び、関係を作っておく

コラム「代替システムにはどんなものを使う？」：バックアップが侵害されると、システムを復旧できない。ヒアリングでも、そうした状況から復旧した組織があった。事案対応の中で、社外とのコミュニケーションに、短期間で使い始められるクラウドのメールやチャットを使った例が多く、そのまま本番の運用に続けた組織も複数あった。海外の拠点とのネットワーク接続を含め、SASE を使うなど、比較的新しいサービスの導入を進めた例もあった。

この教訓集の留意点（IPA が書く）

  • ヒアリング調査の結果がもとで、近年の攻撃に即した事案対処の全体像や、包括的・体系的な方法論を示すものではない。
  • 被害組織が選んだ対応が「必要」「重要」「有効」かは、事前の対策のレベル、被害の状況、優先した方針によって、組織ごとに大きく違う。
  • 教訓の内容には、被害組織の認識と判断、および、IPA による事象の選定・分析に基づく面がある。
  • 法令・規制に関する記載は、一般的な参考情報で、個別の事案への法的判断ではない。最新の法令や、所管官庁・個人情報保護委員会の資料を確認し、必要なら専門家に相談する。

読むときの注意（筆者の整理）

  • 11の教訓の見出しと要点は、教訓集の記述に沿って整理したものです。各教訓の「ヒアリング調査に基づく分析」と「解説」（各項目のページ）は、読んでいないため、載せていません（未確認）。

用語メモ

二重脅迫
データを暗号化して身代金を要求するだけでなく、暗号化の前に盗んだデータを暴露すると脅して、支払いを迫ること。
EDR
パソコンやサーバーの端末での、不審な動きを検知し、対応するための仕組み。
BCP（事業継続計画）
災害や攻撃などで、事業が止まったときの、継続と復旧の計画。
フォレンジック調査
攻撃の痕跡を分析して、何が起きたかを調べること。
SASE
ネットワークと、セキュリティの機能を、クラウドで一体で提供する仕組み。
