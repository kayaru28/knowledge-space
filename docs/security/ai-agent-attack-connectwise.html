AIエージェントが、攻撃を機械の速さで進めた：Microsoft が確認した、ConnectWise の Cloud Backup のサプライチェーン攻撃と、3時間未満で特権に届いた例

2026年10月21日にMicrosoftが公表した、中国の国家と連携した攻撃者Storm-0940によるAIエージェント（ARTEX）を使った攻撃の自動化と、ConnectWiseのCloud Backupへの侵害について、時系列、攻撃の流れ、Microsoftの対策の案内を、MicrosoftとConnectWiseの公式の資料から整理する。

初回公開 2026-10-25 ／ 更新日 2026-10-25

ひとことで言うと

Microsoft は2026年10月21日、中国の国家と連携した攻撃者「Storm-0940」が、AI エージェントの攻撃用の道具「ARTEX」で、攻撃を自動化していたと公表しました。

2026年9月ごろから、世界の数百の組織を、さまざまな業種にわたって狙い、複数の例で、狙ってからクラウドの特権のアクセスを得るまでが3時間未満でした。Microsoft は、10月に公表された ConnectWise の Cloud Backup（旧 SkyKick）への侵害も、この攻撃者によるものと評価しています。侵害のあと、攻撃者は、ARTEX で、2,250を超えるテナントにサインインを試みました。

Microsoft は、これは、Microsoft 自身の製品やシステムの脆弱性によるものではないと述べています。大半の標的は失敗しましたが、短い時間で、特権を持つクラウドへの永続的なアクセスを得た組織が、多くあったとしています。

何が起きたのか

  • 攻撃者：Storm-0940。Microsoft は「中国の国家と連携した攻撃者」とし、2021年から活動していると述べます。以前から、パスワードスプレー（多数のアカウントに、よくあるパスワードを試す攻撃）と、インターネットに公開されたアプリケーションの悪用で侵入し、既存の OAuth アプリケーションに認証情報を追加して、Microsoft 365 への継続的なアクセスを確保してきました。
  • 道具：ARTEX は、オープンソースの、ペネトレーションテスト（模擬の攻撃で弱点を調べる試験）のための枠組みで、どの AI モデルでも使えます。複数の AI エージェントが、偵察からデータの持ち出しまでの模擬の攻撃を、ほとんど人の手を介さずに進めます。画面と出力は英語が既定ですが、韓国語、中国語、スペイン語、日本語に切り替えられます。
  • 狙われた業種：航空宇宙・防衛、自動車、化学、エネルギー、金融、政府、法務、製造、メディア、軍事、半導体、ソフトウェア、技術、シンクタンクと非営利団体など。
  • 速さ：AI で自動化すると、大量の通信とログが出て、警報が鳴りえます。しかし、速さのために、守る側が、警報に対応して、調整して侵入を除くための時間は、ほとんどないと、Microsoft は述べています。

ConnectWise の件の時系列

  • 10月10〜14日：8つの組織の327アカウントを狙った、組織をまたぐ自動のパスワードスプレー。151,000回を超える失敗したサインインがあり、10月11日に1分あたり2,900回でピークになり、1日に111,000回以上が集中しました。48のアカウントは1,000回を超える失敗を受け、応答の約98%はロックアウトでした。この攻撃では、成功したサインイン、トークンの発行、Graph の呼び出し、ディレクトリの変更は確認されていません。
  • 10月15日：人気のクラウドバックアップのアプリケーション（ConnectWise）が侵害されたという公の報告が出始めました。示された侵害の痕跡が、先のパスワードスプレーと同じ範囲のインフラと一致したと、Microsoft は述べています。
  • 10月16日：ConnectWise が最初の勧告を公開しました。Cloud Backup（旧 SkyKick）に関連するアプリケーションの認証情報への、不正なアクセスを確認したとしています。
  • 10月24日：ConnectWise は、独立した専門家とともに、サービスを管理された順序で復旧していると更新しました（インフラ全体の証明書の更新を含む）。既存のバックアップのアーカイブは、暗号化され、隔離され、保全されていて、侵害の兆候はなく、ほかの ConnectWise の製品やサービスに影響の兆候はないとしています。

攻撃の流れ

Microsoft の対策の案内

接続は無効のまま

影響を受けた ConnectWise のアプリケーションの接続は、ConnectWise から復旧の案内があるまで、無効のままにします。

削除の前に保全する

企業のアプリケーションを、最初の対応として削除しません。取り返しのつかない変更の前に、設定と証拠を保全します。

10月15日以降を確認する

少なくとも10月15日以降のサービスプリンシパルのサインインを確認します（記録があれば10月1日まで）。成功と失敗を分けて、公表された IP アドレスだけに限らず確認します。

変更を調べる

アプリへの認証情報の追加、新しいアプリや所有者、同意、特権ロールの割り当て、認証方法や条件付きアクセスの変更を調べます。疑わしい活動は、権限を取り消し、認証情報を更新します。

影響を受けるアプリケーションが存在することや、認証が成功したことは、必ずしも、顧客のデータにアクセスされたことを意味しないと、Microsoft は述べています。

筆者の整理：攻撃者は、パスワードスプレーや、OAuth アプリの悪用という、以前からの手口を使っています。変わったのは、AI エージェントで、偵察から、認証、持続まで、複数の経路を、同時に、昼夜を問わず進められることです。ConnectWise のアプリが、顧客のテナントですでに信頼されていたことで、利用者のサインインなしに、環境へ入れました。連携しているアプリの権限を、最小にしておく意味が大きくなります。アプリケーションの認証情報の変更は、元のアプリを無効にしても残る裏口になりえます。別のまとめ（国内の情報漏えい）のアルカディアの件と同じく、侵入の入口を塞ぐだけでは足りません。
