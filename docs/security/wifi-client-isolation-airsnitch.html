Wi-Fi の「クライアント分離」は破れる：AirSnitch（NDSS 2026）が示した、調べたすべての機器への攻撃と、有効だった対策

カリフォルニア大学リバーサイド校などの研究者が、2026年2月の NDSS で発表した論文「AirSnitch」の、攻撃の種類、評価した11機種と大学のネットワークの結果、対策、開示の経過を、論文の本文をもとに整理する。攻撃には、同じネットワークにつながっていることが前提。

初回公開 2026-11-20 ／ 更新日 2026-11-20

ひとことで言うと

Wi-Fi の「クライアント分離（AP 分離）」は、同じネットワークにつながった端末どうしの直接の通信を止めて、内部からの攻撃を防ぐ機能です。カリフォルニア大学リバーサイド校（UCR）と KU Leuven の研究者は、この機能の安全性を体系的に分析し、調べたすべてのルーターとネットワークが、少なくとも1つの攻撃で破られたと、2026年2月の NDSS で報告しました。

攻撃者は、すでにそのネットワークにつながっている端末（ゲスト用など）であることが前提で、被害者への通信の注入、被害者のインターネット向けの通信の傍受、両方を合わせた中間者攻撃（MitM）が可能になります。論文は、Netgear R8000 での実験で、MitM の確立に約2秒と書いています。

なぜ破れるのか：3つの原因

1. 放送用の鍵の管理が甘い

多くの Wi-Fi の実装は、放送・マルチキャストの通信を、共有の「グループ一時鍵（GTK）」で守る。クライアント分離を有効にしても、全端末がこの鍵を持つため、内部の攻撃者が、これを悪用して、被害者に直接パケットを注入できる。Passpoint という標準も、この点で、設計上の欠陥がある、と書く

2. 分離が、MAC か IP の一方だけ

多くのベンダーは、第2層（MAC）でだけ分離し、第3層（IP）には引き継がない。第2層の宛先をゲートウェイの MAC、第3層の宛先を被害者の IP にすると、AP は受け入れ、ゲートウェイが被害者へ転送してしまう（ゲートウェイバウンシング）

3. 端末の識別の同期が弱い

被害者の MAC アドレスを偽って、同じネットワークの別の接続口（別の BSSID や別の AP）につなぐと、AP が、被害者が移動したと誤認し、被害者向けの下りの通信を攻撃者へ回す（ポートスティーリング）

論文が示す攻撃の種類

  • GTK の悪用：共有の鍵で暗号化した放送のフレームの中に、被害者宛ての個別のパケットを入れる。暗号の方式（WPA2、WPA3）に依存しない。
  • ゲートウェイバウンシング：上記の2。被害者への通信の注入に使う。
  • ポートスティーリング：上記の3。被害者の下りの通信、ルーターの MAC を偽れば、他端末の上りの通信も横取りできる。
  • ブロードキャストの反射、マシン・オン・ザ・サイド、偽の AP：表の組み合わせで、複数の経路から、同じ目的を達する。偽の AP は、被害者を切り離して、偽の AP につながせる。
  • 中間者攻撃（MitM）：傍受と再注入を組み合わせて、双方向の通信に割り込む。確立したあとは、リンク層のすべての通信を傍受でき、未修正の（D）TLS の実装の脆弱性があれば、HTTPS の復号につながりうる、と書く。

評価の結果

論文の評価（著者の実験）
対象結果
家庭用のルーター7機種（Netgear R8000、Tenda RX2 Pro、D-Link DIR-3040、TP-Link Archer AXE75、ASUS RT-AX57、DD-WRT、OpenWrt 24.10）GTK の悪用、マシン・オン・ザ・サイド、偽の AP は、7機種すべてで、クライアント分離を破った。WPA2 と WPA3 のどちらでも成立
BSSID 間（ゲストとメイン）単独の AP の5機種で、ゲストとメインの分離を迂回して、フレームやパケットを注入できた。6機種で、上り・下りのポートスティーリングができ、うち4機種で、ゲストとメインの壁を破れた
企業向け4機種（Ubiquiti の2機種、Cisco Catalyst 9130、LANCOM LX-6500）Ubiquiti の2機種は、ゲートウェイバウンシング、GTK の悪用、ブロードキャストの反射、ポートスティーリングに弱かった。Cisco と LANCOM も、GTK の悪用と下りのポートスティーリングに弱かった
端末の OSmacOS、iOS、Android は、GTK で暗号化された放送のフレームの中の、個別の IP パケットを受け入れた。Linux の drop_unicast_in_l2_multicast を有効にすると、IPv4 の ping は落とすが、IPv6 と ARP の確認には、なお応答した
2つの大学のネットワーク（別の国）実際のネットワークでも、攻撃が成立した。研究者は、ほかの利用者がいない週末の夜に、被害者の IP を宛先にした範囲で試験した。WPA2/3-Enterprise が、個別の資格情報で守る、という通説を覆す、と位置づける
企業の構内（RADIUS）AP と認証サーバーの間の RADIUS の通信を、上りのポートスティーリングで盗める、と報告。パスワードの解読や、偽の AP の設置につながる、と書く

Netgear R8000 では、ゲスト用の SSID から、信頼するメインの SSID の被害者の通信全体に割り込む MitM を、約2秒で確立できました。その間、被害者は YouTube の動画をストリーミングしており、大きな遅れを感じなかった、と書いています。

論文が挙げる対策

  • VLAN で分ける：ゲストの SSID を別の VLAN に置くと、攻撃の多くが無効になる。TP-Link EAP613 で確認。DD-WRT と OpenWrt は、ゲストとメインを別の内部スイッチ（ブリッジ）に分けると、ポートスティーリングを防げた。Tenda RX2 Pro は、同じ MAC を2つの BSSID で同時に使わせない仕組みで、防げた。
  • なりすましの防止：無線側で、偽のゲートウェイの MAC を拒否する、複数の BSSID に同じ MAC が現れたら切断する、IP のなりすましを防ぐ、といった方策が有効。
  • グループ鍵の保護：クライアントごとに、ランダムな GTK を使う（Passpoint の DGAF Disable）。放送の通信は、端末ごとのユニキャストに変換される。
  • 端末間の暗号化：第2層のフレームの中身を、端末ごとの固有の鍵で、端末間で暗号化する。この論文の攻撃は、Wi-Fi の通信の機密性、完全性、真正性を損なうため、その保護に使える、と書く。

開示と、その後（論文の記述）

  • 各ベンダーに、90日を超える修正の準備の期間を与え、緩和の前には、脆弱性を公開しなかった。
  • 多くのベンダーが応答し、一部は、すでにソフトウェアの更新を出した。
  • Wi-Fi Alliance は、Passpoint の v3.4 で、IGTK のランダム化の不足に対応した。LANCOM は、結果を認め、グループ鍵をランダム化する選択肢を加えた。Ubiquiti は、緩和の方法を検討中。D-Link は、検証用に、ルーター2台を提供した。
  • ほかのベンダーは、製品を評価中。層をまたぐ脆弱性のため、時間がかかる、と書く（執筆の時点）。

用語メモ

クライアント分離（AP 分離）
同じ Wi-Fi の端末どうしが、直接通信できないようにする機能。標準ではなく、ベンダーごとの実装。
GTK（グループ一時鍵）
放送・マルチキャストの通信を暗号化する、ネットワーク全体で共有する鍵。
BSSID
1つの AP が持つ、仮想的なネットワークの接続口。ゲスト用、メイン用などに分かれる。
中間者攻撃（MitM）
通信の途中に割り込んで、傍受や改ざんをする攻撃。
Passpoint
公衆の Wi-Fi への自動接続などを定めた、Wi-Fi Alliance の仕様。
RADIUS
企業の Wi-Fi で、認証に使われる、標準的な仕組み。
